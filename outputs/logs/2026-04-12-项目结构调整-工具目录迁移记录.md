# 项目结构调整：工具目录迁移记录

## 变更概述

本次调整将原项目中的 `tools/` 目录和 `tests/` 目录中的脚本统一移动到 `.env/` 目录，并在 `.gitignore` 中将 `.env/` 目录排除在版本控制之外。

## 变更详情

### 1. 目录结构调整

| 原目录/文件 | 新位置 | 状态 |
|-------------|--------|------|
| `tools/` 目录内容 | `.env/` 目录 | 已迁移 |
| `tests/` 目录中的脚本 | `.env/` 目录 | 已迁移 |
| `tools/` 目录 | 已删除 | 不再保留 |
| `tests/` 目录（部分） | 可能保留其他内容 | 仅脚本迁移 |

### 2. .gitignore 更新

`.gitignore` 文件已包含以下条目：
```
.env/
.venv/
```

确保 `.env/` 目录下的所有内容不会被 Git 跟踪。

## 对知识库的影响

### 1. 知识库边界明确
- `.env/` 目录内容**不属于** llm wiki 知识库的编译范围
- 这些是本地维护工具和测试脚本，不应被纳入 `raw/` → `wiki/` → `outputs/` 工作链
- Agent 在处理知识库时，应忽略 `.env/` 目录中的内容

### 2. 维护工作分离
- 知识库的构建、编译、健康检查等维护操作现在有专门的工具目录
- 这些工具仅用于维护知识库结构，不构成知识库内容本身
- 工具的变更不直接影响知识库的知识网络

### 3. 版本控制优化
- 避免将本地工具和配置误提交到知识库仓库
- 保持知识库内容纯净，专注于原始资料、来源卡、概念页和输出

## 对 Agent 的指示

### 1. 工作范围界定
- Agent 在处理本仓库时，**不应**将 `.env/` 目录中的文件视为知识库内容
- Agent **不应**尝试编译、分析或引用 `.env/` 目录中的脚本
- Agent **不应**修改 `.env/` 目录结构，除非明确要求维护工具

### 2. 维护操作记录
- 如果 Agent 使用 `.env/` 中的工具进行知识库维护，应在 `outputs/logs/` 中记录操作
- 工具的使用方法和结果应记录在日志中，但工具代码本身不纳入知识库

### 3. 知识库完整性检查
- 进行知识库健康检查时，Agent 应关注 `raw/`、`wiki/`、`outputs/` 目录
- `.env/` 目录的状态不影响知识库的结构完整性和链接健康度
