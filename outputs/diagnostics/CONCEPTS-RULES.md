# Wiki Concepts 层完整规则

> **本规则补充并完善 `wiki/schema.md` 中关于 concepts 层的规则。当两个文件冲突时，本文优先级更高。**

---

## Part 1: 阶段设计规则（Phase Strategy）

### 全局编译阶段框架

所有主题编译应遵循统一的 **4 阶段** 模式：

#### Phase 0：规划与预评估（1 天）
**入口**：确定主题范围后，立即执行

**动作**：
1. 扫描 `raw/notes/` 和 `raw/web/` 中该主题的资源
2. 统计资源总数，分类记录
3. **关键**：列出该主题的"核心概念清单"（Tier 1）
   - 定义：该领域的 3-5 个核心理论框架或模型
   - 示例（因果推断）：Causal Diagram、Rubin Causal Model、Propensity Score、DoWhy Framework、Causal Inference Methods
4. 评估是否需要多个子阶段（来源数量 > 50）

**输出**：编译计划文档，包含资源统计与核心概念清单

---

#### Phase 1：资源整理与框架建立（2-3 天）
**入口**：规划完成后开始

**动作顺序**（严格按此顺序）：

1. **raw 层清理**：
   - 补齐所有 `raw/notes/**/index.md` 的 frontmatter（source_type、created_at、topics）
   - 检查命名规则是否符合 `YYYY-MM-DD-标题.md` 或 `repo-xxx.md`

2. **sources 层生成**：
   - 为所有 raw 资源生成来源卡到 `wiki/sources/[topic]/`
   - 每张卡包含：摘要、核心要点、概念链接、source_path 回链

3. **indexes 层创建**：
   - 创建 `wiki/indexes/[topic]/` 目录
   - 生成 3 个索引页：
     - `[主题]总索引.md`（定义、概念导航、来源清单）
     - `[主题]来源清单.md`（按日期/类型/概念的完整表格）
     - `[主题]阅读地图.md`（分阶梯学习路径）

4. **concepts 层：创建 Tier 1 核心概念页**：
   - 依据"核心概念清单"创建 Tier 1 页面
   - 页数：通常 3-5 个
   - 每页内容：定义、关键原理、应用案例、常见误区、相关概念链接
   - **关键**：在索引页中建立"核心概念"导航块

**输出**：
- `wiki/sources/[topic]/*.md`（来源卡）
- `wiki/indexes/[topic]/*.md`（3 个索引）
- `wiki/concepts/[topic]/*.md`（Tier 1 核心概念页，3-5 个）
- `wiki/concepts/[topic]/index.md`（概念导航）

**质量检查**：
- ✅ 所有来源卡的 source_path 都指向现存 raw 文件
- ✅ 所有索引页都列出了完整的来源卡清单
- ✅ 所有 Tier 1 概念页都在索引和彼此间相互链接

---

#### Phase 2：资源扩展与方法深化（根据资源量，1-2 周）
**入口**：Phase 1 验收通过后开始

**触发条件**：
- 新增 10+ 来源卡
- 或需要补充新的方法级别概念

**动作顺序**：

1. **sources 层扩展**：
   - 新增来源卡至 `wiki/sources/[topic]/`
   - 保持卡片质量（摘要、要点、链接）

2. **indexes 层扩展**：
   - 更新"来源清单"表格
   - 更新"阅读地图"，添加新资源对应的学习路径
   - 优化"总索引"中的概念分类

3. **concepts 层：补充 Tier 2 方法级概念页** ⭐ 关键
   - **触发条件**：
     - 来源卡中频繁出现某个方法名称（2+ 来源）
     - 或该方法对主题很重要但 Tier 1 概念页中没有专题讲解
   
   - **识别流程**：
     ```
     for 每张新来源卡:
       提取核心方法和技术术语
       if 频率 >= 2 or 重要性高:
         flag 为"需要新增概念页"
       end if
     end for
     ```
   
   - **Tier 2 页面数量**：通常 3-5 个（不超过 Tier 1 数量）
   
   - **Tier 2 与 Tier 1 的关系**：
     - Tier 2 应在"相关概念"中链接到 Tier 1
     - Tier 1 应在相关 section 中反向链接到 Tier 2

4. **交叉引用完善** ⭐ 严格要求
   - 每创建一个 Tier 2 页面后，立即更新相关 Tier 1 页面
   - 检查清单：
     ```
     新建工具变量.md 后应在以下页面添加链接：
     - [ ] Causal-Inference-Methods.md（方法库总览）
     - [ ] Rubin-Causal-Model.md（RCM 章节）
     - [ ] Causal-Diagram.md（因果图相关应用）
     - [ ] 索引页中的概念导航块
     ```

5. **索引入口补齐**：
   - 每个新概念页必须在以下位置有入口：
     - `wiki/concepts/[topic]/index.md`（主题概念导航）
     - `wiki/indexes/[topic]/[总索引].md`（概念导航块）
     - `wiki/indexes/[topic]/[阅读地图].md`（学习路径中的相关位置）

**输出**：
- `wiki/sources/[topic]/*.md`（新增来源卡）
- `wiki/indexes/[topic]/*.md`（更新的索引）
- `wiki/concepts/[topic]/*.md`（新增 Tier 2 概念页，3-5 个）
- 更新的 Tier 1 概念页（补充 Tier 2 反向链接）

**质量检查**：
- ✅ 所有新来源卡都在索引中列出
- ✅ 所有新概念页都有 Tier 1 反向链接
- ✅ 所有概念页都在 3 个索引页中有入口
- ✅ 没有孤立概念页（无链接、无索引）

---

#### Phase 3：链接深化与健康检查（1 天）
**入口**：Phase 1 和 Phase 2 完成后

**动作**：

1. **完整性检查**：
   - [ ] 每个概念页都在 `wiki/concepts/[topic]/index.md` 中有入口
   - [ ] 每个概念页都在至少一个索引（总索引 或 阅读地图）中被引用
   - [ ] 每个 Tier 2 概念页都被至少一个 Tier 1 概念页链接

2. **交叉引用完善**：
   - [ ] Tier 1 ↔ Tier 2 双向链接完整
   - [ ] 相关概念页间的链接是否遗漏
   - [ ] 是否有"重复概念"应该合并

3. **内容同步**：
   - [ ] Tier 1 和 Tier 2 概念页间是否有内容冲突
   - [ ] 来源卡引用是否正确指向概念页

4. **来源追踪**：
   - [ ] 每个概念页是否有至少 1 个来源卡支撑
   - [ ] 来源卡是否都在"sources"部分列出

**输出**：
- 更新的概念页（补充缺失链接）
- 健康检查报告
- 可选：合并重复概念页

---

### Phase 设计的重要约束

1. **顺序强制**：Phase 0 → 1 → 2 → 3，不可跳过
2. **阶段间依赖**：
   - Phase 1 的 sources 是 Phase 2 识别新概念的基础
   - Phase 2 的新概念页必须在 Phase 3 中验证完整性
3. **多主题协调**：
   - 不同主题可以并行进行各自的 Phase 1-3
   - 但应在同一个 Phase 内协调（避免某主题 Phase 1 与另一主题 Phase 3 同时进行导致混乱）

## Part 2: 概念页粗细粒度划分规则

### 分类标准

#### Tier 1：框架级核心概念
**定义**：该领域的理论框架、模型或基础体系

**特征**：
- 被该主题的多个子概念所引用
- 篇幅较大（300-400 行）
- 通常在 Phase 1 创建
- 数量：通常 3-5 个

**示例**（因果推断）：
- Causal Diagram（因果图）
- Rubin Causal Model（RCM）
- Propensity Score（倾向评分）
- DoWhy Framework（DoWhy 框架）
- Causal Inference Methods（方法库）

**内容结构**：
```markdown
# [概念名]

## 定义与核心思想
## 关键概念与术语
## 框架与原理
  - 理论基础
  - 关键假设
  - 主要步骤
## 应用场景
  - 场景 1
  - 场景 2
  - 场景 3
## 与其他概念的关系
  - 相关 Tier 2 概念：[[工具变量]]、[[断点回归设计]]
## 常见陷阱与误区
## 参考资源与来源卡
```

---

#### Tier 2：方法级专项概念
**定义**：Tier 1 框架下的具体方法、技术或工具

**特征**：
- 在 Tier 1 中被引用但缺乏专题讲解
- 篇幅中等（250-350 行）
- 通常在 Phase 2 创建
- 数量：通常 3-5 个

**示例**（因果推断）：
- 工具变量（IV，Instrumental Variable）
- 断点回归设计（RDD，Regression Discontinuity）
- 因果发现（Causal Discovery）
- 流行病学研究设计（Case-Control、Cohort）
- 反事实推理（Counterfactual Reasoning）

**内容结构**：
```markdown
# [方法名]

## 定义与直观理解
## 基本原理
  - 核心假设
  - 数学表达
  - 为什么有效
## 必要条件 / 适用范围
## 实现步骤
  - 步骤 1
  - 步骤 2
  - 步骤 3
## 应用案例（2-3 个）
## 常见陷阱与误区
## 与 Tier 1 的关系
  - 属于 [[Causal-Inference-Methods]]
  - 扩展 [[Rubin-Causal-Model]]
## 参考来源卡
```

---

#### Tier 3：应用级专题（可选）
**定义**：特定领域或应用场景下的深度讨论

**特征**：
- 出现频率较低或高度专门化
- 篇幅较小（150-250 行）
- 在 Phase 2+ 创建
- 数量：可有可无

**示例**（因果推断可能的 Tier 3）：
- 机器学习中的因果推理
- 医疗决策中的反事实分析
- 政策评估中的 DID 应用

**内容结构**：
```markdown
# [应用专题名]

## 背景与问题
## 应用方案
  - 如何应用该方法
  - 特殊考虑
## 案例分析
## 常见问题
## 相关概念
```

---

### 粗细粒度判断流程

当遇到新概念时，使用以下流程判断应该创建什么层级的页面：

```
if 该概念是主题的核心框架:
  → 创建 Tier 1
  → 在 Phase 1 创建
elif 该概念是框架下的重要方法 AND 出现频次 >= 2:
  → 创建 Tier 2
  → 在 Phase 2 创建
  → 在相关 Tier 1 中添加反向链接
elif 该概念高度专门化:
  → 考虑创建 Tier 3
  → 或在相关 Tier 2 中作为 subsection
else:
  → 在相关概念页中作为 subsection 或链接
  → 不单独创建页面
end if
```

## Part 3: 交叉引用与链接维护规则

### 链接类型

| 链接类型 | 方向 | 触发时机 | 示例 |
|---|---|---|---|
| 框架引用 | Tier 1 → Tier 2 | Phase 2 新建 Tier 2 时 | Causal-Inference-Methods → 工具变量 |
| 反向引用 | Tier 2 → Tier 1 | Phase 2 新建 Tier 2 时 | 工具变量 → Causal-Inference-Methods |
| 方法引用 | Tier 1/2 → 相关方法 | 内容编写时 | RCM → Tier 2 方法 |
| 来源链接 | 概念页 → 来源卡 | Phase 1/2 完成时 | 反事实推理 → 2026-04-16-因果推理初探7 |
| 索引链接 | 索引 → 概念页 | Phase 1/2 完成时 | 阅读地图 → 工具变量 |

### 维护检查清单

**每创建一个新概念页后，必须执行以下检查**：

```
[ ] Step 1：在 wiki/concepts/[topic]/index.md 中补入口
[ ] Step 2：在相关 Tier 1 概念页中添加反向链接
[ ] Step 3：在 wiki/indexes/[topic]/总索引.md 的概念导航块中补入口
[ ] Step 4：在 wiki/indexes/[topic]/阅读地图.md 中补入学习路径
[ ] Step 5：检查来源卡是否都在"sources"部分列出
[ ] Step 6：运行健康检查：确认无孤立概念页、无断链
```

### 反向链接维护规则

**规则**：创建 Tier 2 页面时，必须在至少 1 个 Tier 1 页面中添加反向链接

**执行方式**：

1. **识别相关 Tier 1 页面**：
   - 该 Tier 2 方法的核心框架是什么？
   - 示例：工具变量的核心框架是"Rubin Causal Model"和"Causal-Inference-Methods"

2. **添加反向链接**：
   ```markdown
   ## 相关方法与工具
   - [[工具变量]]（IV）— 处理内生性的关键工具
   - [[断点回归设计]]（RDD）— 自然实验的利用方式
   ```

3. **验证**：
   - Tier 1 页面中的 Tier 2 链接是否完整？
   - 是否有新增的 Tier 2 方法但 Tier 1 中没有反向链接？

## Part 4: 概念页与来源卡链接规则

### 链接建立时机

| 阶段 | 动作 | 规则 |
|---|---|---|
| Phase 1（来源卡生成）| 来源卡 → 概念页链接 | 在来源卡中，根据内容识别关键概念，添加 [[概念名]] 链接 |
| Phase 1（概念页创建）| 概念页 → 来源卡链接 | 在概念页的"参考资源"section 中列出支撑来源 |
| Phase 2（新概念识别）| 来源卡识别新概念 | 扫描新来源卡，识别未被现有概念页覆盖的概念 |
| Phase 3（验证）| 完整性检查 | 确认每个概念页至少有 1 个来源卡支撑 |

### 一对多关系处理

**场景 1：一个概念页对应多个来源卡**（正常）
```
反事实推理.md
  → sources: 2026-04-16-因果推理初探7.md
  → sources: 2026-04-16-因果推理初探8.md
```

**场景 2：多个来源卡引用同一个概念页**（正常）
```
2026-04-16-因果推理初探5.md → [[工具变量]]
2026-04-15-因果推断简介2.md → [[Rubin Causal Model]]
```

**场景 3：一个来源卡对应多个概念页**（正常）
```
2026-04-15-吸烟致癌...md
  → [[流行病学研究设计]]
  → [[因果推断方法]]
  → [[病例对照研究]]
```

### 来源卡新概念识别流程

每次补充新来源卡时，执行以下流程：

```
for 每张新来源卡:
  提取核心概念和技术术语 → 列表 L
  
  for 每个概念 in L:
    if 概念已在现有 Tier 1/2 页面中:
      → 在来源卡中添加 [[概念名]] 链接
    elif 概念的出现频次 >= 2（在多张来源中）:
      → flag 为"待新建概念页"
    else:
      → 作为一个参考术语记录，不单独创建页面
    end if
  end for
end for
```

## Part 5: 健康检查与维护规则

### 自动健康检查清单

**频率**：每次 Phase 完成后执行；月度例行检查

**检查项**：

| 项目 | 检查方式 | 标准 | 修复动作 |
|---|---|---|---|
| 孤立概念页 | 搜索无入口的概念页 | 每个页面至少 1 个索引链接 | 补充入口或删除 |
| 断链检查 | 扫描所有 wikilinks | 0 条断链 | 修复或更新链接 |
| 引用完整性 | Tier 2 是否都被 Tier 1 反向链接 | 100% 覆盖 | 补充反向链接 |
| 来源追踪 | 每个概念页是否有来源卡 | 至少 1 个来源 | 添加来源或删除 |
| 重复检查 | 是否有概念页重复定义 | 0 条重复 | 合并或添加区分说明 |

### 月度维护节奏

```
周一：扫描孤立概念页和断链
周三：检查 Tier 1-2 反向链接完整性
周五：检查来源追踪和重复概念
      + 生成月度健康报告
```

## Part 6: 概念页与索引入口关系规则

### 必需的索引入口

每个新建概念页必须在以下位置有入口：

1. **主题概念导航**（必需）
   ```
   wiki/concepts/[topic]/index.md
   ```

2. **主题总索引**（必需）
   ```
   wiki/indexes/[topic]/[主题]总索引.md 
   的"核心概念"导航块
   ```

3. **阅读地图**（可选但推荐）
   ```
   wiki/indexes/[topic]/[主题]阅读地图.md
   的相关学习路径中
   ```

### 可达性验证流程

```
for 每个概念页:
  计数 = 0
  if 页面在 wiki/concepts/[topic]/index.md 中:
    计数 += 1
  if 页面在 wiki/indexes/[topic]/* 中:
    计数 += 1
  if 页面被至少 1 个其他概念页反向链接:
    计数 += 1
  
  if 计数 < 2:
    → flag 为"入口不足"，补充链接
  end if
end for
```

## Part 7: 规则冲突解决

### 何时创建新概念页的判断矩阵

| 条件 | 创建 Tier 1 | 创建 Tier 2 | 作为 subsection | 不创建 |
|---|---|---|---|---|
| 核心框架 | ✅ Phase 1 | - | - | - |
| 重要方法 + 频次≥2 | - | ✅ Phase 2 | - | - |
| 重要方法 + 频次=1 | - | ⚠️ 评估 | ✅ 推荐 | - |
| 专门工具 | - | - | ✅ | - |
| 应用案例 | - | - | ✅ | - |
| 细节技术 | - | - | - | ✅ |

### 重复概念的合并规则

如果发现两个概念页内容重叠 > 50%：

1. 确认是否真的重复，还是有区分
2. 如果确实重复，选择一个为"主页"
3. 将"副页"改为重定向或合并
4. 更新所有链接指向主页
