# Wiki Concepts 层规则诊断报告

## 执行概述

本诊断通过对比以下文件：
- `wiki/schema.md`（总体规则）
- `wiki/concepts/index.md`（层级职责）
- `CLAUDE.md`（编译流程）
- 实际编译历史（LLM、机器学习、时间序列、因果推断等多主题）

识别了 **wiki/concepts 层的 7 大规则缺失**，适用于所有主题的编译工作。


## 诊断发现

### ✅ 现有规则

| 规则 | 位置 | 内容 | 完整度 |
|---|---|---|---|
| 流程顺序 | schema.md L92-96 | raw → sources → indexes → concepts | ✓ 明确 |
| 质量约束 | schema.md L107 | 2+ 来源或单来源核心主题 | ✓ 明确 |
| 层级职责 | concepts/index.md L14-24 | 沉淀概念、方法、工具页面 | ✓ 明确 |
| 收录范围 | concepts/index.md L20-24 | 定义、方法、工具三类 | ✓ 明确 |

| 维护流程 | concepts/index.md L31-35 | 抽取→新建→补入口（3 步）| ⚠️ 抽象 |

### ❌ 规则缺失（7 大类）

#### 1. **Phase 编译策略缺失** ⚠️ 严重
**现象**：
- Phase 1 中创建了 5 个"核心概念页"（Causal-Diagram、RCM 等）
- Phase 2 中完全没有考虑补充"细粒度概念页"（工具变量、RDD 等）
- 导致后续编译中频繁出现"忘记更新 concepts"的问题

**规则缺失**：
- [ ] 缺少"Phase 1 vs Phase 2"的概念页创建策略
- [ ] 缺少"何时应该补充细粒度概念页"的判断准则
- [ ] 缺少在索引扩展时同步评估概念页需求的触发条件

**示例**：
```
Phase 1（资源整理期）
  ├─ raw 元数据补齐
  ├─ wiki/sources 来源卡生成
  ├─ wiki/indexes 索引创建
  └─ wiki/concepts 核心概念页（定义、框架级）❌ 无规则

Phase 2（资源扩展期）
  ├─ 新增 raw 文件
  ├─ wiki/sources 来源卡补充
  ├─ wiki/indexes 索引扩展
  └─ wiki/concepts 细粒度概念页补充（方法级、技术级）❌ 无规则
```


#### 2. **概念页粗粒度 vs 细粒度的划分规则缺失** ⚠️ 严重
**现象**：
- 无法区分何时应该创建"核心概念页"vs"细粒度概念页"
- Causal-Diagram 和 断点回归设计 应该如何区分？
- 导致概念页体系层次混乱

**规则缺失**：
- [ ] 缺少"核心概念"vs"方法概念"的分类标准
- [ ] 缺少"概念页深度"的分级标准
- [ ] 缺少不同层级概念页的组织方式

**建议划分**：
```
Tier 1（框架级核心概念）：对应主题的理论框架
  例：[主题]-Overview（综述总览）、[主题]-Framework（核心框架）
  特征：高度通用、被多个子概念引用、占篇幅大（300+ 行）

Tier 2（方法级概念）：框架下的具体方法
  例：[Tier1]-Method-A（具体算法）、[Tier1]-Method-B（具体技术）
  特征：方法级、有明确的适用条件、占篇幅中（250-350 行）

Tier 3（应用级概念）：特定领域的应用或变体
  例：[主题]-Domain-Application（领域应用）、[主题]-Use-Case（应用案例）
  特征：应用级、高度专门化、占篇幅中（200-300 行）
```


#### 3. **跨概念页引用关系维护规则缺失** ⚠️ 中等
**现象**：
- 创建新的细粒度概念页后，没有规则指导应该如何更新现有概念页
- Causal-Inference-Methods.md 中本应链接到"工具变量""RDD"等具体页面，但没有
- 导致概念页之间形成"单向链接"而非"网络"

**规则缺失**：
- [ ] 缺少"创建新概念页后更新相关概念页"的检查清单
- [ ] 缺少"反向链接"的维护规则（Tier 1 → Tier 2）
- [ ] 缺少"概念页交叉引用覆盖率"的健康检查标准

**示例**：新建 `[Tier2-方法名].md` 后应该：
```
1. 在 [Tier1-综述页].md 中添加 [[Tier2-方法名]] 链接
2. 在 [Tier1-理论页].md 中添加 [[Tier2-方法名]] 链接（如相关）
3. 在 [Tier1-框架页].md 中添加 [[Tier2-方法名]] 链接（如相关）
4. 在 [主题]/index.md 中补入口

❌ 当前没有规则来驱动这个过程
```


#### 4. **概念页与来源卡链接规则缺失** ⚠️ 中等
**现象**：
- 来源卡 sources/causal-inference/ 中的 29 张卡，应该如何链接到概念页？
- 一个概念页应该链接多少个来源卡？
- 来源卡如何识别"新概念"需要创建页面？

**规则缺失**：
- [ ] 缺少"来源卡 → 概念页链接"的建立标准
- [ ] 缺少"一对多"vs"多对一"关系的处理规则
- [ ] 缺少"来源卡中新概念的识别流程"

**示例**：
```
来源卡：YYYY-MM-DD-[主题]-文章标题.md（含 [Tier2-方法名] 的内容）
  → 应该链接到概念页：[[Tier2-方法名]]
  → 但如果概念页不存在？应该：
    a) 在来源卡中创建占位链接？
    b) 在相关 Tier1 概念页中添加"to be expanded"注记？
    c) 添加到主题索引的"待创建概念页"列表？

❌ 当前无规则
```


#### 5. **健康检查和维护规则缺失** ⚠️ 中等
**现象**：
- 没有规则定义如何检查"孤立概念页"（无来源引用、无上级链接）
- 没有规则定义"概念页重复"的识别与合并标准
- 没有规则定义"过期概念页"的清理标准

**规则缺失**：
- [ ] 缺少"孤立概念页"的识别标准
- [ ] 缺少"概念页重复度检查"的规则
- [ ] 缺少"概念页更新频率"的维护节奏
- [ ] 缺少"概念页版本冲突"的解决规则

**建议检查清单**：
```
- 孤页检查：每个概念页是否至少有 1 个来源卡和 1 个索引入口？
- 链接完整性：概念页间的相关链接是否都已补充？
- 内容同步：相关概念页间的内容是否有矛盾？
- 覆盖率：主题中的重要概念是否都有对应页面？
```


#### 6. **索引入口与概念页关系规则缺失** ⚠️ 中等
**现象**：
- 创建新概念页后，应该在哪些索引中补入口？
- 如何验证概念页的可达性？
- 没有规则约束

**规则缺失**：
- [ ] 缺少"新建概念页必须补入口的索引清单"
- [ ] 缺少"概念页可达性验证"的规则
- [ ] 缺少"概念页导航结构"的设计规则

**示例**：新建 `[Tier2-方法名].md` 应该在：
```
1. wiki/concepts/[主题]/index.md（主题概念导航）
2. wiki/indexes/[主题]/[主题]总索引.md（主题索引的概念导航块）
3. wiki/indexes/[主题]/[主题]阅读地图.md（学习路径中的相关位置）
4. 相关 Tier1 概念页的"相关方法"section

❌ 当前无自动检查机制
```


#### 7. **全局编译阶段设计规则缺失** ⚠️ 严重
**现象**：
- 没有全局的"Phase 设计"规则
- 不同主题的编译应该都遵循相同的阶段划分吗？
- 如何保证所有主题的编译质量一致？

**规则缺失**：
- [ ] 缺少"多主题编译的全局阶段设计"
- [ ] 缺少"阶段之间的依赖关系"的规则
- [ ] 缺少"并行编译"vs"顺序编译"的协调规则

**建议设计**：
```
全局编译框架（统一所有主题）：

Phase 0（规划）
  ├─ 确定主题范围和来源分布
  ├─ 预估资源卡数量
  └─ 识别关键概念清单

Phase 1（资源整理）[2-3 天]
  ├─ raw 层：补齐 frontmatter、检查命名
  ├─ sources 层：生成来源卡
  ├─ indexes 层：创建索引框架
  └─ concepts 层：创建 Tier 1（框架级）核心概念页

Phase 2（资源扩展）[根据资源量]
  ├─ sources 层：补充新来源卡
  ├─ indexes 层：扩展索引与学习路径
  └─ concepts 层：补充 Tier 2+（方法/应用级）概念页

Phase 3（链接深化）[1 天]
  ├─ 概念页间的交叉引用完善
  ├─ 来源卡 → 概念页链接建立
  ├─ 索引 → 概念页入口补齐
  └─ 健康检查与修复

Phase 4（沉淀）[可选]
  ├─ 高价值输出生成
  └─ 回流到 wiki/indexes
```


## 规则缺失的根本原因

### 设计问题
1. **流程规则过于高层**：schema.md 说"最后补概念页"，但没有阶段设计
2. **缺少反馈循环**：创建来源卡后应该自动触发"概念页需求评估"，但无规则
3. **缺少约束条件**：schema.md 有"质量约束"但没有"维护约束"

### 工程问题
1. **缺少检查清单**：编译后应该跑什么验证？无清单
2. **缺少自动化指导**：新建概念页后应该做什么？无自动触发
3. **缺少版本管理**：概念页如何标记版本和更新时间？无规则
