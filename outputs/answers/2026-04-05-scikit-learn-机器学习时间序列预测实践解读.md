# scikit-learn 机器学习时间序列预测实践解读

## 这篇示例真正讲了什么

这篇 scikit-learn 官方示例表面上是在演示 `HistGradientBoostingRegressor` 做下一时刻预测，但真正值得沉淀的不是具体模型名，而是一条非常标准的机器学习时间序列实践链路：

1. 先把序列通过滞后特征和窗口特征转成监督学习表格
2. 再用通用回归模型训练预测器
3. 然后用保留时间顺序的切分方式评估
4. 最后用分位数回归表达预测不确定性

这条链路的意义在于，它把“时间序列预测”从纯统计建模或纯深度学习建模中拉出一条工程化中线，让通用 ML 工具链也能进入时序任务，但前提是你不能把时序数据当普通 i.i.d. 表格数据来处理。

## 最关键的实践启示

### 1. 滞后特征是桥，不是细节

如果不做滞后特征，通用回归器根本看不到时间依赖。页面里用 Polars 构造滞后特征，本质上是在做一件事：把“序列问题”重写成“用过去若干时刻去预测未来”的监督学习问题。

这说明在机器学习时间序列预测里，模型往往不是第一优先级，样本组织方式才是。很多时候，滞后项、滚动统计、日历特征、协变量设计，决定的上限比换个模型更大。

### 2. 随机切分会高估模型效果

示例先用随机 `train_test_split`，得到的 MAPE 约为 `0.389`；再改用 `TimeSeriesSplit` 做时间序列保序切分，首个时间切分的 MAPE 约为 `0.443`。这个差异本身就说明了问题：随机切分把未来信息的统计结构“提前泄漏”给了训练阶段，因此结果更乐观。

这不是一个 scikit-learn 特有问题，而是所有表格化时序预测都会遇到的问题。只要你把时序样本改造成监督学习样本，验证阶段就必须重新尊重时间顺序。

### 3. `gap`、训练窗口和测试窗口都是评估设计的一部分

示例里 `TimeSeriesSplit` 不只是简单换了个 API，还显式设置了：

- `gap=48`
- `max_train_size=10000`
- `test_size=3000`

这说明时间序列评估不是“切一下就行”，而是在定义一个更接近真实部署条件的回测实验。`gap` 用来减少潜在泄漏，训练窗口大小影响历史记忆范围，测试窗口大小影响结果稳定性和计算成本。

换句话说，评估设计本身就是模型设计的一部分。

### 4. 点预测不够，最好同时给出不确定性

示例进一步用 `loss="quantile"` 训练 5%、50%、95% 分位数模型。这个动作很重要，因为它把“预测一个值”升级成“预测一个区间”。对实际业务来说，区间往往比点值更有决策意义。

页面里的观察也很有代表性：白天区间更宽、夜间更窄，说明高波动时段的不确定性更大。这类结论对容量规划、库存配置、风控预留都比单一均值预测更实用。

## 对后续建模的直接操作建议

如果你后面在 `tsproj_ml` 或其他机器学习预测项目里复用这篇思路，可以直接检查这几项：

1. 当前特征构造里是否明确包含滞后项、窗口统计和时间索引特征
2. 训练/验证切分是否仍然混入随机打乱
3. 是否需要显式设置 `gap`
4. 当前报告是不是只给点预测，没有给区间预测
5. 评估报告里是否同时给出 `MAPE`、`MAE`、`RMSE`，以及适合区间预测的 pinball loss

如果这 5 项里有 2-3 项还没有做，说明你的模型流程还没有真正进入“规范的机器学习时间序列预测”阶段。
