# 5 个 Repo 仓库专题编译综述

本轮对 `raw/repos/` 下的 5 个仓库做了主题化编译，没有新建单独的 repo 专题，而是把它们分别回流到现有主题中。

## 主题归属结果

- `control-algorithm-proj` → `control-algorithms`
- `storage_mpc_project` → `control-algorithms`，并跨链到 `power-market-trading`
- `dowhy` → `causal-inference`
- `ele-trading` → `power-market-trading`
- `rlproj` → `reinforcement-learning`

## 这轮编译带来的结构变化

### 控制算法

控制算法主题不再只停留在 PID、模糊控制和机器人学基础，而是明确开始吸收现代控制方法与工程模板：

- `control-algorithm-proj` 提供了 `PID / LQR / MPC / iLQR / NMPC` 的可运行示例链
- `storage_mpc_project` 提供了储能场景的 MPC 工程模板
- 新增的 [[现代控制方法]] 把这两类仓库吸收到同一条学习路径里

### 因果推断

因果推断主题原本已经有较完整的 DoWhy 理论与入门来源。本轮新增的是“官方仓库工程入口”：

- `dowhy` 不再只是概念框架或入门文章，而是可追溯的官方源码、文档、示例与测试入口
- 因此主题结构从“DoWhy 作为框架概念”升级为“DoWhy 概念 + 官方源码入口”

### 电力市场交易

电力市场交易主题原本已经完成了主轴文档、方法桥接和工具支线重构。本轮进一步补上代码实现层：

- `ele-trading` 作为研究型原型代码库进入主题工程实现层
- `storage_mpc_project` 作为储能控制模板从控制算法主题跨链进入建模支线
- 主题结构从“文档主轴 + 方法页”推进到“文档主轴 + 研究原型代码 + 储能控制模板”

### 强化学习

强化学习主题原本偏教程、算法综述与 LLM 对齐。本轮补上了一个更基础、更轻量的代码实践入口：

- `rlproj` 当前主要覆盖 bandit solver 与 regret 可视化
- 因此主题中新增了“本地工程实践”入口，并通过 [[多臂老虎机与累积懊悔]] 与基础 RL 概念连接

## 这 5 个仓库的角色分层

- **工程实现层**：`control-algorithm-proj`、`storage_mpc_project`、`ele-trading`
- **官方框架入口**：`dowhy`
- **轻量实践入口**：`rlproj`

## 本轮结果

这轮编译的价值，不在于“又多了 5 张来源卡”，而在于知识库开始更稳定地吸收代码仓库这一类材料：

- 对已有主题形成工程层补强
- 避免 repo 材料留在 `raw/repos/` 中成为暗资产
- 让“概念 -> 方法 -> 代码仓库”成为更清晰的复用路径
