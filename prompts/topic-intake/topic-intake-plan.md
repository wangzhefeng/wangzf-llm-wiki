请先阅读我指定的专题目录或专题清单，然后为“把这个专题纳入当前知识库”输出一份可执行计划。

背景约束：
- 当前知识库采用 `raw -> wiki/sources -> wiki/indexes -> wiki/concepts -> outputs` 分层
- `raw/` 是唯一摄取入口
- 本地旧文档统一放在 `raw/local-notes/`
- 原始目录优先保留，不要直接覆盖或拆散旧文档
- 新 wiki 页面统一使用普通 Markdown 和 frontmatter
- 新页面不要沿用旧站点里的 `<style>`、`<details>`、Hugo 特有结构
- 图片统一迁移到 `assets/attachments/<topic-slug>/`

请按下面结构输出：

```md
<proposed_plan>
# <专题名>纳入知识库计划

## Summary

用 1-2 段说明：
- 这个专题是什么
- 原始资料在哪里
- 这轮整理聚焦什么，不聚焦什么
- 是“保留原文 + 新建 wiki 映射”，还是别的方式

## Key Changes

- 列出这轮要新增或更新的目录、索引页、来源卡、概念页
- 明确是否新增 `raw/local-notes/<topic>/` 入口文件
- 明确图片迁移规则
- 明确旧目录是否保留

## Public Interfaces / Types

- 给出本轮会使用的 frontmatter 字段
- 给出来源卡、概念页、索引页的命名约定
- 给出路径规则和链接规则

## Test Plan

- 如何验证原始目录未被破坏
- 如何验证来源卡、概念页、索引页是否补齐
- 如何验证图片路径和互链正确
- 如何验证没有残留旧路径或旧站点结构

## Assumptions

- 写清楚你做这个计划时依赖的前提
- 如果主题太大，明确首轮只纳入哪一部分
</proposed_plan>
```

额外要求：
- 优先按“先来源卡，后索引页，再概念页”的顺序规划
- 如果专题体量太大，主动缩成一个首轮子主题
- 把暂不整理的边缘内容登记到来源清单或历史文档清单里，避免遗漏
- 不要直接输出实现结果，只输出计划
