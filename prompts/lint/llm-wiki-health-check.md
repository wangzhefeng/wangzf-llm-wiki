请基于当前知识库，执行一轮系统性的 LLM Wiki 健康检查。

## 检查架构：两层互补

本检查采用 **自动化工具（结构层）+ LLM 分析（语义层）** 两层互补架构：

| 层级 | 工具 | 检查内容 |
|------|------|---------|
| 结构层（自动化） | `uv run scripts/run.py check` | 10 项：wikilinks / frontmatter / naming / 附件 / 目录 / 新鲜度 / status / source_path / 旧命名 / 相对链接 |
| 语义层（LLM 驱动） | 本 prompt | 5 维：矛盾检测 / 过时声明 / 调研缺口 / 缺失概念 / 输出回流 |

## 执行顺序

### 阶段 A：结构层基线（先跑工具）

```bash
uv run scripts/tools/wiki_lint.py --output detailed
```

解读结果，按三级严重度处理：
- ❌ 错误 → 必须修复
- ⚠️ 警告 → 建议修复，记录边界
- ℹ️ 信息 → 关注但不阻塞

将自动化检查结果作为阶段 B 的前置输入。

### 阶段 B：语义层深度检查（LLM 执行）

基于知识库内容，从以下 5 个维度进行语义分析：

#### 1. 矛盾检测
- 检查不同概念页对同一术语的定义是否一致
- 检查来源卡之间的结论是否相互矛盾
- 重点检查：同一主题下，不同时间写入的页面是否存在冲突声明
- 输出：矛盾位置 + 证据路径 + 建议解决方向

#### 2. 过时声明检测
- 利用 `content freshness` 检查结果，重点关注超过 90 天未更新的页面
- 结合 `raw/web/` 中的新来源，判断旧概念页的声明是否已被新证据取代
- 输出：过时页面列表 + 对应新来源 + 更新建议

#### 3. 调研缺口识别
- 对比 `raw/` 与 `wiki/sources/`，找出"有原始资料但无来源卡"的缺口
- 检查各主题索引中标注为"待补充"或缺失的条目
- 识别：哪些主题的概念网络明显薄弱（来源卡多但概念页少）
- 输出：缺口清单 + 优先级排序

#### 4. 缺失概念检测
- 扫描 wikilink 错误列表，识别"被引用但未创建"的概念页
- 检查索引页中引用的概念是否都存在对应页面
- 输出：待创建概念列表 + 建议来源基础

#### 5. 输出回流检查
- 检查 `outputs/` 中的高价值结果是否已回链到 `wiki/`
- 判断是否有一次性问答值得沉淀为概念页或来源卡
- 输出：待回流项 + 目标位置

## 输出规范

结果必须落地到文件，不在对话中口头汇报：

```markdown
# LLM Wiki 健康检查报告（YYYY-MM-DD）

## 结构层结果
- 自动化检查命令与结果摘要（来自阶段 A）
- 三级严重度统计

## 语义层发现
### 矛盾检测
### 过时声明
### 调研缺口
### 缺失概念
### 输出回流

## 综合判断
- 当前知识库最关键的 3 个结构问题
- 当前知识库最重要的 3 个内容缺口
- 整体健康评分（A-F）

## 下一步
1. 按优先级排序的 3-5 个行动项
```

## 落地要求

- 覆盖更新 `wiki/log_lint.md`（唯一主报告出口）
- 增量追加 `wiki/log.md`（`## [YYYY-MM-DD] lint | 全面健康检查`）
- 如果产出新的 answers/syntheses，写入 `outputs/` 并回链
- 不新增独立日志文件（如 `YYYY-MM-DD-知识库-健康检查-第X轮.md`）
