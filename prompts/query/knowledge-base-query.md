请基于当前知识库，执行一轮“围绕现有 wiki 的问答 / 研究 / 输出回流”。

适用场景：
- 想回答一个具体问题，而不是继续摄取新来源
- 想比较现有来源、概念和索引中的不同观点
- 想把一次查询沉淀成 `outputs/answers/` 或 `outputs/syntheses/`

执行约束：
- 只优先使用当前库中已经存在的 `wiki/`、`outputs/`、`raw/` 内容
- 除非用户明确要求补新来源，否则不要把这轮 query 退化成 intake
- 先列证据路径，再给判断
- 如果证据不足，要明确指出缺口，不编造结论
- 高价值结果不能只停留在对话里，必须落地成 Markdown 文件

请按下面顺序执行：

1. 明确问题边界
   - 把用户问题压缩成 1 句可执行问题
   - 判断这更适合：
     - 单次回答：写入 `outputs/answers/`
     - 阶段性综述：写入 `outputs/syntheses/`

2. 先做证据准备
   - 列出最相关的：
     - `wiki/sources/`
     - `wiki/concepts/`
     - `wiki/indexes/`
     - 必要时补充已有 `outputs/`
   - 标出：
     - 已有共识
     - 冲突或边界
     - 证据不足的地方

3. 再给回答或研究结论
   - 回答必须引用具体条目名
   - 优先组织成：
     - 问题是什么
     - 当前库里已有哪几类证据
     - 能得出的稳定判断是什么
     - 还不能下结论的部分是什么
     - 下一步最值得继续问什么

4. 把结果写入文件
   - 单次回答写到：`outputs/answers/YYYY-MM-DD-主题-用途.md`
   - 阶段性综述写到：`outputs/syntheses/YYYY-MM-DD-主题-用途.md`
   - 如果同一天已有同名文件，优先更新，不重复造新版本

5. 做最小回流
   - 在相关索引页补“派生输出”入口
   - 如果这轮形成了稳定的新问题，补到相关问题地图
   - 如果这轮形成了稳定新判断，再补到相关概念页或索引页

6. 补一条操作记录
   - 在 `outputs/logs/` 写一页本轮 `query` 记录
   - 至少记录：
     - 问题
     - 使用了哪些证据页
     - 产出了什么文件
     - 做了哪些回流
     - 还有什么缺口

输出要求：
- 不只回答对话，必须实际写文件
- 最终汇报按三部分组织：
  - 做了什么
  - 怎么验证
  - 剩余风险
- 如果判断当前问题证据不足，也要把“证据不足的原因”和“下一步该补什么”落到结果文件里
