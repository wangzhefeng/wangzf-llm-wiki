请基于当前知识库，执行一轮系统性的“知识库健康检查”。

背景约束：
- 当前知识库采用 `raw -> wiki/sources -> wiki/indexes -> wiki/concepts -> outputs` 分层
- `raw/` 是唯一摄取入口
- `wiki/sources/` 只放来源摘要卡
- `wiki/indexes/` 只放专题索引、阅读地图、来源清单、维护清单
- `wiki/concepts/` 只放概念页
- `outputs/` 只放派生结果
- `raw/local-notes/` 中的历史原文不要求全部出现在知识图谱里，但必须可追溯

请按下面 5 个维度检查：

1. 摄取层检查
- `raw/` 里是否有新增资料还没归类
- 是否有资料还停留在根目录，没有进入 `raw/`
- `raw/local-notes/` 的历史专题是否都有专题清单
- 关键附件、图片、截图是否已经本地化

2. 来源卡检查
- `raw/` 中的关键来源是否都已有 `wiki/sources/` 摘要卡
- 来源卡是否缺少 `source_type`、`source_path`、`created_at`、`topics`、`related_concepts`、`status`
- 是否存在“有原文、没来源卡”的核心资料
- 是否存在来源卡内容过薄，只是占位但还没有信息量

3. 索引页检查
- 每个专题是否至少有总索引和阅读地图
- 总索引是否能区分“概念页”和“来源页”
- 是否存在新增专题已整理，但首页或索引没有入口
- 是否存在边缘内容已经进入来源层，但没有在来源清单或历史清单登记

4. 概念页检查
- 核心概念页是否能链接回至少 1 张来源卡
- 概念页之间是否存在必要互链
- 是否存在定义重复、概念重名、边界不清
- 是否存在来源很多但概念页还没长出来的主题簇
- 是否存在概念页完全孤立，缺少索引入口或来源支撑

5. 输出回流检查
- `outputs/` 里是否已经有高价值结果还没回链到 `wiki/`
- 是否有一次性问答值得沉淀成索引补丁、概念补丁或候选来源
- 输出命名是否清楚，可否长期回看

检查时请优先参考：
- [[知识库维护检查索引]]
- [[知识库健康检查清单]]
- [[README]]
- [[raw/README]]
- [[wiki/README]]
- [[outputs/README]]

执行流程要求：
- 开始检查前，先阅读 `outputs/answers/知识库-健康检查-最新.md`，优先确认其中列出的延续待办是否已处理
- 本轮检查结果必须覆盖更新 `outputs/answers/知识库-健康检查-最新.md`
- 本轮检查完成后，必须增量更新 `outputs/logs/知识库-健康检查-日志.md`（检查与修复都写在同一文件）
- 输出写完后，还要把这份结果回链到 `[[知识库维护检查索引]]` 与 `[[知识库健康检查清单]]`；如果首页 `[[README]]` 里有“最近检查结果”入口，也要同步更新
- 下次开始维护前，默认先根据最近一次健康检查结果确定优先级，而不是重新从零散观察开始

输出要求：

```md

- 用 3-6 条概括当前知识库最重要的状态判断

- 问题是什么
- 证据路径
- 为什么它重要

- 同上

- 列出这轮确认没有问题的关键项

## 建议的下一步
1. 给出按优先级排序的 3-5 个下一步
2. 每个下一步说明应该改哪一层：`raw / sources / indexes / concepts / outputs`

## 可直接执行的修复动作
- 如果存在低成本修复项，单独列出
```

结果落地要求：

- 检查完成后，不只在对话里汇报，必须实际写文件到：
  - `outputs/answers/知识库-健康检查-最新.md`
  - `outputs/logs/知识库-健康检查-日志.md`
- 不再新增 `YYYY-MM-DD-知识库-健康检查-第X轮.md` 作为 answers 主报告
- 不再新增 `YYYY-MM-DD-知识库健康检查记录.md` 或 `YYYY-MM-DD-知识库健康检查修复记录.md` 作为独立日志
- 输出落地后，再补充说明：
  - 已写入的输出文件路径
  - 已更新的回链入口

额外要求：
- 不要泛泛而谈，尽量给出具体文件路径
- 区分“结构问题”和“内容薄弱但可接受的问题”
- 如果某些问题只是首轮刻意暂缓，不要误报成错误，要标记为“已登记但未展开”
- 如果没有发现严重问题，要明确说出当前阶段最大的真实瓶颈是什么
