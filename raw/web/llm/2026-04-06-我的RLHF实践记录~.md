01

**流程介绍**

1\. 我使用的 base model 是 face book 的 OPT 1.3b，是一个参数量较小的模型，用到的微调数据集是 Dahoas/rm-static。

这个 base model 预训练用到的语料基本上是英文，所以下面的对话例子都用英文。

从这个截图中，可以看到，预训练后的模型有理解和生成的能力，但对话能力较弱。

![图片](data:image/svg+xml,%3C%3Fxml version='1.0' encoding='UTF-8'%3F%3E%3Csvg width='1px' height='1px' viewBox='0 0 1 1' version='1.1' xmlns='http://www.w3.org/2000/svg' xmlns:xlink='http://www.w3.org/1999/xlink'%3E%3Ctitle%3E%3C/title%3E%3Cg stroke='none' stroke-width='1' fill='none' fill-rule='evenodd' fill-opacity='0'%3E%3Cg transform='translate(-249.000000, -126.000000)' fill='%23FFFFFF'%3E%3Crect x='249' y='126' width='1' height='1'%3E%3C/rect%3E%3C/g%3E%3C/g%3E%3C/svg%3E)

2\. 第一步进行 SFT，SFT 关注到的数据集中的正例，是在预训练中没见过的 token，这一步也教会了模型如何对话。

SFT 后的模型准备两份，一份用来当 RL 过程中的 actor 来更新 policy，另一份作为 reference model 用来计算损失函数时用的 KL 散度，防止 RL 后的模型偏离原本的 base model 太远。

我们来看看同样的对话内容，SFT 后的模型的回复：

![图片](data:image/svg+xml,%3C%3Fxml version='1.0' encoding='UTF-8'%3F%3E%3Csvg width='1px' height='1px' viewBox='0 0 1 1' version='1.1' xmlns='http://www.w3.org/2000/svg' xmlns:xlink='http://www.w3.org/1999/xlink'%3E%3Ctitle%3E%3C/title%3E%3Cg stroke='none' stroke-width='1' fill='none' fill-rule='evenodd' fill-opacity='0'%3E%3Cg transform='translate(-249.000000, -126.000000)' fill='%23FFFFFF'%3E%3Crect x='249' y='126' width='1' height='1'%3E%3C/rect%3E%3C/g%3E%3C/g%3E%3C/svg%3E)

经过了 SFT 的模型，已经具备了初步的对话能力。

3\. 第二步，训练一个 reward model。

训练 reward model 和 SFT 一样，用的是同一个数据集，但是不同之处在于，reward model 相比于 SFT，能关注到负例，能利用到 rejected answer。

目前一步的 reward 设计只考虑到了 Pairwise Ranking Loss，暂时没有加入rule-based reward。

reward model 训练完后 ，也有两个用途，一个冻结参数，另一个用来初始化critic model。

4\. 第三步，RLHF。

在这一步，我们用上了冻结参数不参与更新的 reward model、reference model。

使用第一步 SFT 得到的 actor model 作为 policy model 更新参数，critic model 使用 reward model 来初始化参数。

在这一步的 PPO 算法中，GAE 通过使用多步时序差分残差计算出优势估计值 Ât，PPO 随后利用这个 Ât 和概率比 rt(θ)，通过 clipped 目标函数来构建并优化最终的策略损失。

有些同学不太理解为什么需要 critic model，他们可能是先做的 NLP、LLM，才接触到 RL ，我作为一个先接触 RL，再接触 LLM 的同学，斗胆解释一下：

reward model 生成的奖励是对序列整体的奖励分数，只在生成序列的最后一个位置加上这个奖励分数，这样的奖励分数是具有稀疏性的，如果只用这个最终的 reward 会导致方差过大。

critic model 可以预测长期累积奖励的期望值，critic model 输出的 values 是按照时间步，也即 token 位置给出的，能通过 TD 估计价值，平衡偏差和方差。

下面我直接贴出了 deepspeed chat 的 GAE 计算源码，里面有 values 和 rewards 在 GAE 计算中是怎么使用的：

```sql
def get_advantages_and_returns(self, values, rewards, start):        # Adopted from https://github.com/CarperAI/trlx/blob/main/trlx/models/modeling_ppo.py#L134        lastgaelam = 0        advantages_reversed = []        length = rewards.size()[-1]        for t in reversed(range(start, length)):            nextvalues = values[:, t + 1] if t < length - 1 else 0.0            delta = rewards[:, t] + self.gamma * nextvalues - values[:, t]            lastgaelam = delta + self.gamma * self.lam * lastgaelam            advantages_reversed.append(lastgaelam)        advantages = torch.stack(advantages_reversed[::-1], dim=1)        returns = advantages + values[:, start:]        return advantages.detach(), returns
```
