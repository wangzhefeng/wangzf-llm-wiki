# 1. 线程目标

- 从“做健康检查”起步，逐步升级为“把第五轮健康检查待修项全部修复”。
- 交付重点不是对话结论，而是仓库内可追溯的报告、修复、索引回流和日志记录。
- 约束条件：脏工作区持续存在；不得覆盖用户已有改动；默认不做 commit/push。

# 2. 实际完成内容

- 产出第五轮健康检查报告与操作记录，并持续更新共享索引入口。
- 修复明确缺陷：outputs 回流缺口、raw/web 附件断链、索引统计过期、deep learning 入口缺失。
- 将 `machinelearning` 来源层从 12 张分批补到 68 张，达到 `raw -> sources` 全覆盖。

# 3. 操作过程摘要

## 阶段一：先 lint 再修

- 做了什么：先做 repo 级扫描，按问题类别形成报告（覆盖率、断链、回流、弱互链、统计一致性）。
- 为什么这样做：避免边改边猜，先建立可验证的问题清单。
- 结果：锁定主矛盾为 `machinelearning/deeplearning` 积压 + 导航与互链质量。

## 阶段二：先快修结构断点

- 做了什么：优先修附件路径、outputs 回流入口、过期统计、deep learning 最小入口。
- 为什么这样做：先恢复“可导航、可读、可追溯”基础状态。
- 结果：非大规模 backfill 项快速清零，减少后续噪音。

## 阶段三：分批 backfill 大积压

- 做了什么：按高密度子目录批量补卡（ensemble -> feature-engine -> clustering -> 评估/监督/无监督剩余）。
- 为什么这样做：大积压必须目录化推进，否则会长期停在“修了一些但始终不闭环”。
- 结果：`machinelearning` 达成 68/68；索引统计与阅读地图同步刷新。

## 阶段四：按“清零口径”收尾

- 做了什么：补齐弱互链、更新问题地图、写收尾日志并重跑验证。
- 为什么这样做：用户指令升级为“都修复”，需要从渐进改善切换为逐项消项。
- 结果：第五轮待修项闭环。

# 4. 关键决策

- 决策 1：采用 `lint -> 修复 -> 回写 -> 复验` 链路，而非一次性“直接修”。
  - 原因：知识库型仓库更依赖结构一致性与可追溯性。
- 决策 2：`machinelearning` 先补来源层，再谈概念扩写。
  - 未选方案：先补概念页。
  - 原因：遵守仓库 `raw -> sources -> indexes -> concepts` 顺序。
- 决策 3：把 `deeplearning` 升格为独立专题而非长期挂在 raw。
  - 原因：体量已达到专题阈值，不再是临时素材堆。
- 决策 4：最后以“问题清零”而非“改善明显”为完成标准。
  - 原因：用户明确要求“都修复”。

# 5. 有效做法

- 将每轮关键动作写入 `outputs/logs/` 并立即挂到共享索引，降低后续线程接续成本。
- 使用固定验证组合：数量校验（`find/wc`）+ 内容扫描（`rg`）+ frontmatter 巡检 + `git status` 边界检查。
- 对大 backlog 采用“子目录批处理 + 每批同步索引统计”的节奏，比随机补卡稳定。
- 在脏工作区中反复确认“仅追加，不回滚，不覆盖已有改动”。

# 6. 问题与摩擦点

- “执行”类短指令未显式定义完成口径，前半段容易停在渐进修复。
- 索引统计和阅读地图易滞后；若不强制同步，会出现“实际已修复但导航仍过期”。
- 缺统一状态板时，待修项跟踪依赖对话上下文，跨轮容易失焦。
- 部分原始文档内容薄弱（占位型 raw），补卡时只能保留锚点，信息增益有限。

# 7. 对 Codex 工作流的启发

- 可固化步骤：
  1. `kb-lint`：产出问题分级清单（含证据路径）
  2. `kb-backfill`：按目录批处理来源层
  3. `kb-backflow`：同步 indexes/README/工作台入口
  4. `kb-closeout`：复验并写收尾日志
- 可固化检查清单：
  - sources frontmatter 完整性
  - raw 覆盖率
  - outputs 回流率
  - 附件可解析路径
  - 索引统计一致性
  - 弱互链节点补强状态
- 适合写入 skill/AGENTS 的规则：
  - 大积压必须按子目录批处理
  - 每批 backfill 必须同步统计与入口
  - 不允许“口头完成”，必须落日志与索引
  - 脏工作区下必须显式避让既有改动
- 应避免反模式：
  - 只修文件不回写导航
  - 只报“修了很多”不定义“已清零”标准
  - 概念层继续先于来源层扩张

# 8. 可复用素材

- 可复用提示模式：先做健康检查并输出问题分类；再按分类修复；最后统一复验并写收尾记录。
- 可复用命令模式：`find ... index.md`、`find wiki/sources/... | wc -l`、`rg` 过期统计扫描、frontmatter 字段巡检、`git status --short`。
- 可复用模板：健康检查报告、修复记录、专题编译记录、收尾记录。
- 可复用目录约定：`outputs/logs/` 作为动作时间线中心，`wiki/indexes/shared/知识库操作记录索引.md` 作为统一入口。
