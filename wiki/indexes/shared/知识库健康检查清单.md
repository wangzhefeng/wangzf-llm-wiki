# 知识库健康检查清单

## 定位说明

这页是知识库的维护操作清单。每次准备继续整理专题、开始新研究，或者感觉库里有点乱时，就从这里开始。它只提供逐项检查的操作条目，不承载工作流导航。

> 整合说明：本页位于 `shared/` 根目录，作为 lint 操作的逐项执行清单；入口导航与运维触发条件以 [[知识库维护检查索引]] 为准。

## 关键资源

- [[知识库维护检查索引]]：lint 执行入口与运维导航
- [[知识库-健康检查-最新]]：最近一次健康检查主报告
- [[知识库-健康检查-日志]]：历史检查记录
- [[LLM-Wiki总索引]]：LLM-Wiki 统一导航入口
- 快速结构巡检：`prompts/maintenance/wiki-lint`
- 全链路体检规范：`prompts/maintenance/knowledge-base-health-check`

## 什么时候执行

- 新纳入一个专题之后
- 连续新增了多份 `raw/` 资料之后
- 做完一轮问答或输出回流之后
- 准备开始下一个专题之前
- 感觉导航链接不对劲时

---

## 第 0 轮：核对 glossary 对齐状态

> 这是结构性前置检查，每次大规模整理前优先执行。

- [ ] 打开 `glossary.md`，确认当前活跃主题列表
- [ ] 检查是否有标注 `(已删除)` 的主题，在以下三层中仍有残留文件：
  - `wiki/indexes/<deleted-topic>/`
  - `wiki/concepts/<deleted-topic>/`
  - `wiki/sources/<deleted-topic>/`
- [ ] 检查 `wiki/sources/**/*.md` 的 `topics:` 字段，是否仍含旧主题名（如历史中的 `deep-learning-theory`、`feature-engine`、`data-analysis`、`programming-tools`）
- [ ] 确认 `glossary.md` 目录名与实际 `wiki/` 子目录名是否一致（历史差异：`feature-engine` vs `feature-engineering`）

**处理原则**：
- 已删除主题有残留 → 决策：彻底删除（推荐）or 标记 `status: archived`
- `topics:` 字段含旧名 → 批量 sed 替换为当前规范名
- 目录名差异仅影响 frontmatter 规范，不影响文件链接，属低优先级

---

## 第 1 轮：看摄取层有没有堆积

- [ ] `raw/` 里最近新增的资料是否都有明确归属
- [ ] `raw/notes/` 里的历史专题是否都有清单页
- [ ] 新资料是否还停留在根目录，而没有进入 `raw/`
- [ ] 重要图片、截图、附件是否已经本地化
- [ ] **【新增】** 检查 raw status 同步：若 `raw/` 中某文件标注 `status: inbox`，但 `wiki/sources/` 中已存在对应源卡，则应将 `status` 更新为 `summarized` 或 `linked`
  - 重点检查：`raw/notes/` 目录（源卡常被批量入库，但 raw status 常忘同步）
  - 参考命令：`grep -r "status: inbox" raw/notes/ -l` → 逐一检查是否已有源卡

优先入口：

- [raw/README](../../../raw/README.md)
- [[运筹优化算法来源清单]]
- [[时间序列预测来源清单]]

---

## 第 2 轮：看来源卡有没有断层

- [ ] `raw/` 里的关键来源，是否都已有 `wiki/sources/` 摘要卡
- [ ] 新增来源卡是否带 `source_type`
- [ ] 本地个人文档来源卡是否带 `source_path`
- [ ] 来源卡是否写清楚 `related_concepts`
- [ ] 是否还存在"有原文、没摘要"的核心资料
- [ ] **【新增】** 检查 `wiki/sources/` 下是否存在无对应主题目录的游离文件夹（如已删除 `tools/`），若有，决策归并或删除

检查原则：

- 先补 `wiki/sources/`
- 不跳过来源卡直接写概念页
- 来源卡只讲"这份材料讲了什么"，不直接写成百科

---

## 第 3 轮：看索引页还能不能导航

### 3A：主题索引完整性

- [ ] 每个活跃主题（见 `glossary.md`）至少有 **3 个** 索引文件：
  - `<主题>总索引.md`（总览 + 概念导航）
  - `<主题>来源清单.md`（所有源卡的表格视图）
  - `<主题>阅读地图.md`（分层学习路径）
- [ ] 每个专题至少有 1 页阅读地图
- [ ] 总索引能区分"概念页"和"来源页"
- [ ] 新增专题后，首页是否补了入口
- [ ] 暂不展开的边缘内容，是否登记在来源清单或历史清单里

优先检查缺文件的主题：

- 运筹优化算法总索引 / [[运筹优化算法阅读地图]]
- 时间序列预测总索引 / [[时间序列预测阅读地图]] / [[时间序列预测来源清单]]

### 3B：控制文件链接有效性

> 控制文件（README.md, wiki/index.md, AGENTS.md, wiki/schema.md）链接断裂会直接导致知识库"门户失效"，必须优先修复。

- [ ] `README.md` 主题入口列表：每个链接指向的文件是否真实存在
- [ ] `wiki/index.md` 主题入口列表：wikilink 指向的文件是否真实存在
- [ ] `AGENTS.md` 中引用的目录路径（如 `wiki/indexes/<topic>/`）是否实际存在
- [ ] `wiki/schema.md` 中描述的目录结构是否与实际吻合

修复原则：
- 已删除主题 → 从入口列表删除对应行
- 新增活跃主题 → 补入入口列表
- 路径引用不存在的子目录 → 改为实际路径

### 3C：shared/ 工作流链接有效性

> `wiki/indexes/shared/` 是全库执行入口，此处断链影响所有下游操作。

- [ ] [[知识库工作台]] 中的"专题入口"列表：每个 wikilink 可以正常解析
- [ ] [[知识库健康检查清单]] 中的检查项链接：指向的文件是否存在
- [ ] [[知识库操作记录索引]] 中的"最近记录"：日志文件是否真实存在于 `outputs/logs/`
- [ ] [[知识库来源与专题摄取索引]]、[[知识库问答与研究工作流]]、[[知识库输出回流工作流]]、[[知识库维护检查索引]]：内部链接是否可解析

修复原则：
- 日志文件被删除 → 从"最近记录"中移除对应行
- 工作流引用的 wikilink 不存在 → 修复文件名或移除引用

### 3D：wikilink 有效性自动扫描

> 用 `tools/wiki_lint.py` 对 wiki/ 下所有 wikilink 做全量有效性扫描，作为 3A/3B/3C 人工检查的补充。

- [ ] 运行 `python tools/wiki_lint.py --report` 生成断链报告
- [ ] 查看 `outputs/logs/wiki-lint-report.md`，确认 **A 类真实断链数为 0**
- [ ] 若存在 A2 占位符链接，用 `python tools/wiki_lint.py --fix` 自动清理
- [ ] 若存在 A1（文件名不匹配）或 A4（旧路径），人工修复后重新扫描

扫描范围说明：
- ✅ 扫描：`wiki/` 下所有 `.md` 文件
- ❌ 跳过：`[[raw/...]]`、`[[outputs/...]]` 前缀（跨层路径，不修复）
- ❌ 跳过：`wiki/log.md`（历史记录文件，包含大量历史链接名）
- B 类（内容缺口，概念页尚未创建）和 C 类（跨层路径）不计入断链数

---

## 第 4 轮：看概念页有没有失联

- [ ] 核心概念页是否都能回链到至少 1 张来源卡
- [ ] 概念页之间是否有必要的互链
- [ ] 是否出现定义重复、概念重名、边界混乱
- [ ] 是否存在只有索引没有概念，或只有概念没有来源支撑的页面
- [ ] 是否有应该新建但还没建的总览页
- [ ] **【新增】** 孤儿概念检查：在 `wiki/indexes/` 下全文搜索，若某个概念页文件名在所有索引中均未出现，则为孤儿页，需补入对应主题索引
  - 检查命令示例：`grep -r "概念页名" wiki/indexes/ --include="*.md"`
  - 常见孤儿来源：新建概念页后未在总索引添加入口

检查原则：

- 概念页负责组织知识，不负责替代原始来源
- 概念页要能回答"这是什么、和谁有关、去哪里继续看"

---

## 第 5 轮：看输出有没有回流

- [ ] `outputs/` 里的高价值结果是否回链到了 `wiki/`
- [ ] **【新增】** `outputs/syntheses/` 中的每个综述文件，是否在至少 1 个主题索引中有入口链接
  - 检查方法：遍历 `outputs/syntheses/*.md`，对每个文件名做 `grep -r "文件名" wiki/indexes/`
- [ ] 一次性问答是否需要沉淀成来源缺口、阅读路线或概念补丁
- [ ] 输出页是否命名清楚，后续还找得到
- [ ] 本轮健康检查结果是否已经落地到 `outputs/answers/`

优先入口：

- `outputs/README`

---

## 执行步骤

1. **第 0 轮（前置）**：先核对 glossary 对齐状态，清理已删除主题残留
2. 看上一轮健康检查结果，确定这轮优先修什么
3. 检查 `raw/` 有没有新资料和错放资料，顺带核对 raw status 同步
4. 补 `wiki/sources/` 缺失来源卡
5. 修 `wiki/indexes/` 的专题入口（控制文件 + shared/ + 主题三件套）
6. 最后补 `wiki/concepts/` 的概念关系，消除孤儿页
7. 如果产出了新的回答、综述或检查报告，先写入 `outputs/`，再回链到 `wiki/`

---

## 每次检查后的收尾动作

- 覆盖更新唯一主报告：`outputs/answers/知识库-健康检查-最新.md`
- 增量更新统一日志：`outputs/logs/知识库-健康检查-日志.md`
- 从本轮结果中提炼 3-5 个下一步，写入"最新主报告"的待办区
- 把这轮发现的缺口回写到相关索引页
- 如果问题很多，优先修复 3 个最影响使用的问题
