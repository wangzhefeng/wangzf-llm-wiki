# 知识库 + Codex Marp 研究型演示稿工作流

这类 slide 不是为了“快速汇报完”，而是为了把一个专题的结构保留下来，方便你后续继续追问、对照和扩展。

## 什么时候用

- 你想为自己保留一份专题回顾稿
- 你需要保留方法链路，而不只是最终结论
- 你之后还会基于这套 slide 继续追加内容

## 内容组织原则

- 允许保留“结论为什么成立”的链路
- 可以保留来源、方法、对照和未完成问题
- 比汇报型更重结构，不一定更重视觉冲击

常见页结构：

1. 标题页
2. 研究对象 / 问题定义
3. 关键来源或背景定位
4. 方法链路 / 工作流
5. 主要发现 1
6. 主要发现 2
7. 对照与边界
8. 待验证问题 / 下一步

## 推荐页数

- 最小可用：8 页
- 常见范围：8 到 15 页
- 超过 15 页时，通常该考虑拆专题而不是继续堆页数

## 适合的输入材料

- 一页或多页 `outputs/answers/`
- 对应的 `wiki/sources/` 来源卡
- 相关 `wiki/concepts/` 与 `wiki/indexes/`
- 一组本地图或多张对照图

相比汇报型，这里可以额外保留：

- 为什么这篇来源重要
- 某个方法和另一个方法的映射关系
- 还没解掉的疑问
- 这次研究和知识库中其他页面的连接位置

## 让 Codex 干什么

推荐直接这样发任务：

- 请基于 `[[某篇结果页]]`，并结合相关概念页和来源卡，生成一份 **研究型** Marp 演示稿。
- 请保留方法链路、来源定位和待研究问题，输出到 `outputs/slides/`。
- 请使用本地图片，不要依赖外链。

如果要做得更稳，可以补上知识入口：

- 请先阅读 `[[某个概念页]]`、`[[某个来源卡]]`、`[[某个总索引]]`，再生成研究型 slide。

## 页面写法

研究型 slide 可以比汇报型保留更多上下文，但仍然要避免两件事：

- 把整篇答案页原样搬进去
- 一页同时塞入多个未区分层级的论点

比较稳的做法是：

- 一页只讲一个层级
- 方法、证据、边界分别占页
- 待研究问题单独成页

## 图片与图示策略

研究型 slide 最适合这几类图：

1. 方法流程图
2. 对照关系图
3. 来源映射图
4. 不确定性或边界图

如果内容本身没有现成图，也可以让 Codex 生成 SVG 示意图，把逻辑关系画清楚。

## 导出与检查

导出 HTML：

```bash
marp outputs/slides/xxx-演示稿.md -o outputs/slides/xxx-演示稿.html
```

导出 PDF：

```bash
marp --pdf --allow-local-files --browser chrome \
  outputs/slides/xxx-演示稿.md \
  -o outputs/slides/xxx-演示稿.pdf
```

至少检查：

1. 是否能看出这份研究的核心问题是什么
2. 是否能看出结论是怎么推出来的
3. 是否能看出它与知识库其他页面的连接关系
4. 是否明确保留了边界和待研究问题

## 一个简单判断标准

如果这份 slide 在一周后还能帮你快速恢复上下文，而不需要重读整篇长文，它就达标了。
