# 知识库 Marp 演示稿构建工作流

这页回答：**如何把知识库中的 outputs 压缩成 Marp 演示稿，以及选哪种类型。**

## 定位说明

演示稿分两类，核心差异是目标受众与内容保留深度：

| 类型 | 适合场景 | 页数 | 核心特点 |
|---|---|---|---|
| **汇报型** | 向他人说明结论 | 6–8 页 | 结论先行，删除推导过程 |
| **研究型** | 自用专题回顾 | 8–15 页 | 保留方法链路、来源映射、待验证问题 |

拿不准时默认先做**汇报型**，因为它更能暴露核心论点是否真的清楚。

## 适合场景

- 刚完成一篇 `outputs/answers/`，想压缩成 slide
- 想保留一份专题研究结构，方便后续继续追问
- 需要给同事或老板做 5–10 分钟口头汇报

## 汇报型演示稿

### 内容结构

1. 标题页
2. 一句话结论
3. 关键证据 1
4. 关键证据 2
5. 风险或边界
6. 下一步动作

每页只保留一个判断，3–5 个要点足够。开头先给结论，不先讲背景。

### 不建议放入的内容

- 过长的方法链路
- 太多来源罗列
- 多个并列但还没收敛的开放问题

### 给 AI 工具的指令模板

```
请基于 某篇结果页 生成一份汇报型 Marp 演示稿，控制在 6–8 页。
请使用本地图片，输出到 outputs/slides/，图片放到 outputs/figures/。
请按"结论、证据、风险、下一步"的顺序组织。
```

### 检查标准

- 第一页是否在 10 秒内说清主题
- 每页是否只讲一个判断
- 删掉一半细节后，slide 反而更清楚 → 做对了

## 研究型演示稿

### 内容结构

1. 标题页
2. 研究对象 / 问题定义
3. 关键来源或背景定位
4. 方法链路 / 工作流
5. 主要发现 1
6. 主要发现 2
7. 对照与边界
8. 待验证问题 / 下一步

可以保留来源、方法、对照和未完成问题；比汇报型更重结构。

### 适合的输入材料

- 一页或多页 `outputs/answers/`
- 对应的 `wiki/sources/` 来源卡
- 相关 `wiki/concepts/` 与 `wiki/indexes/`

### 给 AI 工具的指令模板

```
请基于 某篇结果页，并结合相关概念页和来源卡，生成一份研究型 Marp 演示稿。
请保留方法链路、来源定位和待研究问题，输出到 outputs/slides/。
请使用本地图片，不要依赖外链。
```

### 检查标准

- 是否能看出这份研究的核心问题
- 是否能看出结论是怎么推出来的
- 一周后还能帮你快速恢复上下文 → 达标了

## 共用约束

### 输出目录约定

- `outputs/answers/`：内容底稿
- `outputs/figures/`：本地图片、示意图
- `outputs/slides/`：Marp Markdown 与导出文件

推荐一组对应关系：一篇答案页 + 一组图片目录 + 一份演示稿 Markdown。

### Marp 最小 frontmatter

```yaml
---
marp: true
theme: default
paginate: true
size: 16:9
---
```

### 导出命令

```bash
# 导出 HTML
marp outputs/slides/xxx-演示稿.md -o outputs/slides/xxx-演示稿.html

# 导出 PDF
marp --pdf --allow-local-files --browser chrome \
  outputs/slides/xxx-演示稿.md \
  -o outputs/slides/xxx-演示稿.pdf
```
