# 知识库健康检查清单

这页不是主题内容页，而是知识库的维护工作台。每次准备继续整理专题、开始新研究，或者感觉库里有点乱时，就从这里开始。

- [[知识库建设方法总索引]]
- [[知识库+Codex-时间序列模型开发工作流]]
- [[知识库-健康检查-最新]]

## 什么时候执行

- 新纳入一个专题之后
- 连续新增了多份 `raw/` 资料之后
- 做完一轮问答或输出回流之后
- 准备开始下一个专题之前

## 第 1 轮：看摄取层有没有堆积

- [ ] `raw/` 里最近新增的资料是否都有明确归属
- [ ] `raw/local-notes/` 里的历史专题是否都有清单页
- [ ] 新资料是否还停留在根目录，而没有进入 `raw/`
- [ ] 重要图片、截图、附件是否已经本地化

优先入口：

- [raw/README](../../../raw/README.md)
- [raw/localnotes/README](../../../raw/localnotes/README.md)
- [[运筹优化算法-历史文档清单]]
- [[时间序列预测-历史文档清单]]

## 第 2 轮：看来源卡有没有断层

- [ ] `raw/` 里的关键来源，是否都已有 `wiki/sources/` 摘要卡
- [ ] 新增来源卡是否带 `source_type`
- [ ] 本地个人文档来源卡是否带 `source_path`
- [ ] 来源卡是否写清楚 `related_concepts`
- [ ] 是否还存在“有原文、没摘要”的核心资料

检查原则：

- 先补 `wiki/sources/`
- 不跳过来源卡直接写概念页
- 来源卡只讲“这份材料讲了什么”，不直接写成百科

## 第 3 轮：看索引页还能不能导航

- [ ] 每个专题至少有 1 页总索引
- [ ] 每个专题至少有 1 页阅读地图
- [ ] 总索引能区分“概念页”和“来源页”
- [ ] 新增专题后，首页是否补了入口
- [ ] 暂不展开的边缘内容，是否登记在来源清单或历史清单里

优先入口：

- [[运筹优化算法总索引]]
- [[运筹优化算法阅读地图]]
- [[时间序列预测总索引]]
- [[时间序列预测阅读地图]]
- [[时间序列预测来源清单]]

## 第 4 轮：看概念页有没有失联

- [ ] 核心概念页是否都能回链到至少 1 张来源卡
- [ ] 概念页之间是否有必要的互链
- [ ] 是否出现定义重复、概念重名、边界混乱
- [ ] 是否存在只有索引没有概念，或只有概念没有来源支撑的页面
- [ ] 是否有应该新建但还没建的总览页

检查原则：

- 概念页负责组织知识，不负责替代原始来源
- 概念页要能回答“这是什么、和谁有关、去哪里继续看”

## 第 5 轮：看输出有没有回流

- [ ] `outputs/` 里的高价值结果是否回链到了 `wiki/`
- [ ] 一次性问答是否需要沉淀成来源缺口、阅读路线或概念补丁
- [ ] 输出页是否命名清楚，后续还找得到
- [ ] 本轮健康检查结果是否已经落地到 `outputs/answers/`

优先入口：

- `outputs/README`

## 执行规范入口

- 快速结构巡检：`prompts/maintenance/wiki-lint`
- 全链路体检规范：`prompts/maintenance/knowledge-base-health-check`

说明：本页只保留简版检查清单。完整执行流程、输出格式和落地约束统一以 `prompts/maintenance/knowledge-base-health-check.md` 为准。

## 一次标准维护的顺序

1. 先看上一轮健康检查结果，确定这轮优先修什么
2. 再看 `raw/` 有没有新资料和错放资料
3. 再补 `wiki/sources/` 缺失来源卡
4. 再修 `wiki/indexes/` 的专题入口和阅读路线
5. 最后补 `wiki/concepts/` 的概念关系
6. 如果产出了新的回答、综述或检查报告，先写入 `outputs/`，再回链到 `wiki/`

## 每次检查后的收尾动作

- 覆盖更新唯一主报告：`outputs/answers/知识库-健康检查-最新.md`
- 增量更新统一日志：`outputs/logs/知识库-健康检查-日志.md`
- 从本轮结果中提炼 3-5 个下一步，写入“最新主报告”的待办区
- 把这轮发现的缺口回写到相关索引页
- 如果问题很多，优先修复 3 个最影响使用的问题
