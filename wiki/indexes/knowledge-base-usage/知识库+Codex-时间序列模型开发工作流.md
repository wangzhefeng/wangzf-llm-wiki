# 知识库 + Codex 时间序列模型开发工作流

这页不是主题内容页，而是你以后做时间序列模型开发时的固定起点。目标不是“多看几页笔记”，而是把知识库真正变成 Codex 可用的上下文层。

## 一句话理解这套分工

- 知识库负责提供稳定上下文
- Codex 负责读取上下文、改代码、做检查、产出结果
- Obsidian 负责把这些上下文、结果和互链展示出来

## 什么时候用这页

- 准备开始一个新的时间序列建模任务
- 准备重构已有训练 / 预测 / 评估流程
- 想检查项目里是否存在时间泄漏、坏切分或方法选择错误
- 做完一轮开发，准备把结论回流到知识库

## 第 1 步：先明确这次开发任务

先把任务缩成一句具体话，不要直接说“帮我做时间序列预测”。

推荐写法：

- 做一个基于 LightGBM 的多步负荷预测实验
- 检查 `tsproj_ml` 当前训练流程是否存在时间泄漏
- 把 scikit-learn 的滞后特征方案迁到我的项目里
- 帮我判断这次任务应使用直接预测还是递归预测

## 第 2 步：先给 Codex 指定知识入口

不要让 Codex 自己猜应该读什么。每次至少给 2 到 4 个入口页。

时间序列机器学习开发最常用入口：

- [[时间序列预测总索引]]
- [[机器学习时间序列预测]]
- [[预测特征工程]]
- [[预测模型评估]]
- [[机器学习时间序列多步预测策略]]

如果这次任务和具体来源强相关，再补来源卡：

- [[2026-04-05-scikit-learn-滞后特征预测示例]]
- [[2026-04-05-tsproj-ml-预测策略体系]]
- [[2026-04-05-tsproj-ml-特征工程与输入组织]]
- [[2026-04-05-tsproj-ml-训练测试预测闭环]]

## 第 3 步：向 Codex 发任务时的推荐问法

### 设计类

- 请先阅读 [[机器学习时间序列预测]]、[[预测模型评估]] 和 [[机器学习时间序列多步预测策略]]，再判断这次任务该用哪种多步预测策略。

### 实现类

- 请先阅读 [[预测特征工程]] 和 [[2026-04-05-scikit-learn-滞后特征预测示例]]，然后直接在当前项目里补滞后特征、滚动特征和时间特征。

### 审查类

- 请先阅读 [[预测模型评估]]、[[2026-04-05-scikit-learn-滞后特征预测示例]] 和 [[2026-04-05-tsproj-ml-训练测试预测闭环]]，检查当前项目是否存在随机切分、未来信息泄漏或错误指标。

### 回流类

- 请基于本次开发结果，新增一页 `outputs/answers/` 结果页，并把高价值结论回写到相关概念页和索引页。

## 第 4 步：开发时优先让 Codex 做什么

建议优先让 Codex承担这 4 类工作：

1. 读知识库并提炼“这次任务的设计约束”
2. 直接修改代码、脚本、配置和评估流程
3. 对照知识库检查实现是否偏离既有方法规范
4. 把开发结果回写到 `outputs/` 和 `wiki/`

不建议的用法：

- 不给任何知识入口，直接让 Codex“自由发挥”
- 只让 Codex聊天，不让它实际读文件和改代码
- 开发完以后不回流，结果只留在一次对话里

## 第 5 步：Obsidian 在这套流程中的角色

Obsidian 不是训练工具，也不是推理引擎。它在这套流程里主要负责 4 件事：

1. 做导航
   你从首页、总索引、阅读地图进入，而不是靠回忆找资料。
2. 做关系展示
   你可以用反链、出链和图谱看某个概念由哪些来源支撑。
3. 做沉淀展示
   你能区分 `raw`、`wiki`、`outputs`，不会把原始材料、知识条目和问答结果混在一起。
4. 做长期可维护前端
   Codex 改的是 Markdown 文件，Obsidian 负责把这些文件变成可阅读、可浏览、可复查的工作台。

## 第 6 步：每次开发后的标准回流动作

做完一轮开发，不要停在代码提交或聊天结论。

最小回流动作：

1. 在 `outputs/answers/` 新增 1 页结果记录
2. 如果结论具有稳定性，把它补进 `wiki/concepts/`
3. 如果这次用了新来源，把它补进 `wiki/sources/`
4. 如果阅读入口发生变化，更新 `wiki/indexes/`

## 第 7 步：开发任务结束后的检查

每次开发后，至少检查这几项：

- 这次新增的资料是否已经进入 `raw/`
- 这次参考的关键来源是否有来源卡
- 这次产生的结论是否已经写进 `outputs/`
- 高价值结论是否回写到概念页或索引页

需要系统检查时，直接回到：

- [[知识库健康检查清单]]
- `prompts/maintenance/knowledge-base-health-check`

## 一个最小闭环示例

1. 打开 [[时间序列预测总索引]]
2. 选中 [[机器学习时间序列预测]]、[[预测模型评估]]、[[机器学习时间序列多步预测策略]]
3. 对 Codex 说：请先阅读这些页面，再检查我当前项目的训练、验证和预测流程
4. 让 Codex 直接改代码
5. 让 Codex 再新增一页 `outputs/answers/` 记录本次开发结论
6. 如果有稳定结论，再回写概念页

- 先把结果回流，再开始下一轮开发
