# LLM Wiki 持久化知识库模式来源摘要


- 原文：[[raw/web/knowledge-base/2026-04-05-llm-wiki]]
## 材料定位

这份 Gist 是 Karpathy 对 `LLM Wiki` 模式的原始详细说明，也是目前“个人知识库由 LLM 持续维护”的最完整模式文档之一。和之前偏介绍性的外部文章相比，这份材料更像模式说明书，重点补上了三层架构、三种核心操作、索引与日志、schema 角色和可选工具。

## 关键结论

- 这套模式的核心差异，不是“让 LLM 检索文档”，而是让 LLM 增量维护一个持久化的 wiki，中间层知识会随着资料和问题不断复利。
- 系统可分为三层：`raw sources`、`wiki`、`schema`。其中 `schema` 明确约束 LLM 的工作流，是把 agent 从通用聊天工具变成“有纪律的 wiki 维护者”的关键。
- 三种核心操作是 `ingest`、`query`、`lint`。它们分别对应资料进入、围绕知识库提问、以及周期性健康检查。
- `index.md` 和 `log.md` 承担不同角色：前者是内容导向的索引入口，后者是时间导向的演化日志。
- 这套模式默认支持把高价值查询结果反向写回 wiki，使“提问过程”本身也能成为知识资产。
- 当知识库进一步扩大时，可以引入本地搜索工具或 CLI，但这属于增强层，而不是起步前提。
- Obsidian Web Clipper、图谱视图、Marp、Dataview、git 仓库等都只是可插拔工具，它们服务于模式，而不是定义模式。

## 对知识库的价值

- 它把现有“知识库建设方法”从一般性原则推进到了更明确的系统设计层。
- 它补上了当前库里相对薄弱的 `schema`、`index/log` 与 `operation model` 这几个关键概念。
- 它非常适合作为“知识库构建”主题里的详细模式来源，帮助你以后继续优化 `AGENTS.md`、主题索引页和健康检查流程。
