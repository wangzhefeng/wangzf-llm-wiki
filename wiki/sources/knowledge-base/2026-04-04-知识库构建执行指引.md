# 知识库构建执行指引来源摘要

## 材料定位

这份文档是知识库建设的第一版执行模板。它不是在解释愿景，而是在固定目录结构、页面生成顺序、frontmatter 字段和 Web Clipper 的推荐配置，让 AI 和人都能按同一套规则持续建设这个库。

## 关键结论

- 标准目录结构应清晰区分 `raw/`、`wiki/`、`outputs/`、`prompts/` 和 `assets/`。
- 页面生成顺序必须固定为 `sources -> indexes -> concepts`，避免跳过来源层直接写概念页。
- 原始网页和原始 Markdown 应使用稳定 frontmatter，至少包含 `source_type`、`source_url`、`created_at`、`topics`、`related_concepts` 和 `status`。
- Obsidian Web Clipper 应默认把网页保存到 `raw/web/`，并提前写好统一模板，减少后续手工清理成本。
- 第一轮建设目标应是跑通一个小闭环，而不是一次性把整个知识库设计完整。
- AI 的默认工作方式应是“先读原始来源，再写 wiki，再把高价值结果回流”。

## 对知识库的价值

- 它把 [[2026-04-04-个人知识库诞生设想]] 的原则层转换成了可执行规范。
- 它为后续主题建设、原始资料入库和 Web Clipper 配置提供了统一基线。
- 它也是以后继续修订知识库字段和工作顺序时的首要维护文档。
