# tsproj_ml 特征工程与输入组织来源摘要

## 这个知识单元讲什么

这部分内容解释了机器学习时间序列预测里输入是如何构造的，尤其强调“目标变量滞后”和“全部内生变量滞后”的区别，这是单变量策略和多变量策略分野的关键。

## 核心做法

- 仓库把特征工程作为独立能力层，README 明确提到 `FeaturePreprocessor` 负责特征处理。
- 特征来源至少包括：
  - 时间特征
  - 目标变量滞后
  - 多变量滞后
  - 外生变量
  - 周期编码与节假日类特征
- `MSMD` 一类方法的关键增量，不是换模型，而是把所有内生变量的滞后都纳入输入。

## 输入 / 输出

- 输入：
  - 历史目标序列
  - 其他相关内生变量历史
  - 外生变量
  - 时间索引特征
- 输出：
  - 面向训练的监督学习特征矩阵
  - 面向预测的最近窗口特征

## 关键模块、脚本、配置

- README 提到的关键角色：
  - `FeaturePreprocessor`
  - 多变量 lag feature 扩展逻辑
- README 明确了 `MSMD` 与 `USMD` 的核心区别：
  - `USMD` 主要使用目标变量滞后
  - `MSMD` 使用全部内生变量滞后

## 适用场景

- 多个相关变量共同影响预测目标的场景。
- 想把机器学习预测从“只用目标变量历史”升级到“系统利用多变量相关性”的场景。

## 局限与代价

- 特征维度会显著上升，训练成本和数据质量要求更高。
- 当前首轮还没有逐个核实具体特征函数与参数配置文件。
