# 多求解器工程设计来源摘要

- 原文：[[raw/web/operations-research/2026-04-06-多求解器时代的工程设计-Gurobi,-CPLEX,-SCIP-统一调用方案]]
- 来源：王源（2026-02-27）

## 材料定位

工程实践向文章，讲解如何用**策略模式 + 工厂模式**封装多种求解器（Gurobi/CPLEX/SCIP），实现业务代码与求解器 API 解耦，做到可插拔、可维护、可扩展的多求解器架构。

## 关键结论

- **核心问题**：业务代码直接写死某个求解器 API 导致：强耦合、难切换、难扩展、难测试。
- **解决方案**：策略模式（Strategy Pattern）将每种求解器封装为独立策略类（`GurobiStrategy`、`CplexStrategy`、`ScipStrategy`），统一暴露相同接口；工厂模式（Factory Pattern）按名称创建对应策略对象。
- **设计效果**：新增求解器只需新增一个策略类；A/B 测试不同求解器只需切换工厂参数；Mock 测试可用假求解器替换真求解器。
- **适用场景**：需要对比多种求解器性能、业务代码需跨环境部署（有些环境无 Gurobi 授权）、需要平滑迁移到新求解器。
- **局限**：不同求解器对"不可行"/"超时"等状态的处理存在差异，统一接口需仔细处理边界。
