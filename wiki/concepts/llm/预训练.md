# 预训练（Pre-training）

## 定义与核心要点

预训练是在大规模无标注文本数据上训练语言模型的过程，使其学习通用的语言表示和生成能力。预训练不仅仅是简单的下一词预测任务，而是涉及数据质量、分词策略、计算高效性、分布式训练、优化策略等多方面的系统工程。预训练模型在海量数据上学到的通用知识和语言规律，是后续微调、对齐等工作的基石。

## 为什么重要

预训练是构建现代LLM的最关键一步。通过在互联网规模的文本数据上训练，模型学习到了丰富的语言知识和世界知识，这使得模型可以在各种下游任务上进行快速适应。没有高质量的预训练，无论后续微调多么精细，模型的上限都会受到严重限制。预训练的质量决定了整个模型体系的性能天花板。

## 核心原理

### 1. 数据准备与处理

#### 数据收集
预训练数据来源多样化：
- **网页文本**: CommonCrawl（互联网爬虫数据）
- **书籍数据**: Project Gutenberg、Google Books 等
- **代码**: GitHub、StackOverflow 等编程社区
- **学术资料**: arXiv 论文、学术数据库
- **维基百科**: 高质量百科知识
- **多语言数据**: 支持多语言能力

#### 数据清洗与质量控制
- **去重**: 完全重复和近似重复数据都需去除，减少训练数据浪费
- **语言过滤**: 仅保留高质量语言文本，过滤无关二进制数据
- **内容过滤**: 去除成人内容、恶意内容、隐私信息等
- **质量评分**: 使用启发式规则或ML模型对文本质量打分
- **分布均衡**: 控制不同来源、不同语言、不同主题的比例

#### 数据分布构成
现代LLM预训练数据的典型构成（以LLaMA为例）：
- 网页文本：~45%
- 书籍：~20%
- 代码：~5-10%
- 学术论文：~5%
- 其他（维基、对话等）：~20%

### 2. 分词（Tokenization）

分词是将原始文本转换为token序列的关键步骤。不同的分词算法影响模型的学习效率和推理速度。

#### BPE（Byte Pair Encoding）
- **原理**: 迭代地合并频繁出现的相邻token对
- **优点**: 能处理未见过的单词、词表大小可控
- **缺点**: 对多语言支持不如SentencePiece
- **应用**: GPT-2/3 等模型使用变体

#### WordPiece
- **原理**: 基于似然函数的贪心分割算法
- **特点**: 词表中使用 ##前缀标记子词，便于识别
- **应用**: BERT 及其衍生模型广泛使用

#### SentencePiece
- **原理**: 将文本视为Unicode字符序列，直接应用BPE
- **优点**: 语言无关、不需预先分词、处理多语言和特殊符号更好
- **应用**: LLaMA、Mistral 等现代模型标准选择
- **特点**: 使用特殊token表示空格（如▁），便于恢复原文

#### TikToken
- **创建者**: OpenAI
- **特点**: 针对GPT模型优化，支持特殊token
- **改进**: 在字节级别进行编码，更好地处理多语言

### 3. 缩放定律（Scaling Laws）

缩放定律揭示了模型性能与训练资源的关系，是现代LLM设计的理论基础。

#### Chinchilla 定律
Google 2022年发现的最优配置比例：
- **模型大小与数据量的关系**: 应该使用相等的 flops 去增加模型和数据
- **最优比例**: 计算量应在模型参数和数据token数之间均分
- **实践建议**: 若有 C flops 可用，应分配约 C/(6D) 为模型参数量，C/(6P) 为数据token量（D为参数量，P为token数）
- **应用**: LLaMA、GPT-4 等最新模型都遵循接近的比例

#### 缩放规律的数学形式
性能与规模的幂律关系：
$$L = a \cdot N^{-\alpha} + b \cdot D^{-\beta} + c$$
其中 N 为模型参数、D 为训练数据量、α 和 β 为幂指数（约0.07-0.1）

#### 实际应用指导
- **模型大小**: 100M → 1B → 7B → 13B → 70B → 175B，性能呈幂律递增
- **数据量**: 预训练数据通常为 100B → 1T → 10T tokens
- **计算预算**: 明确计算量（FLOPs）后，可按 Chinchilla 比例分配模型和数据

### 4. 分布式训练策略

预训练通常涉及数十到数百个GPU/TPU，需要高效的分布式训练方案。

#### 数据并行（Data Parallelism, DP）
- **原理**: 同一batch在多个设备上分割处理，每个设备保存完整模型副本
- **通信开销**: 梯度平均化需要AllReduce操作
- **适用**: 模型能放入单个设备内存时

#### 分布式数据并行（DDP）
- **特点**: PyTorch 标准实现，基于 Ring AllReduce 优化
- **性能**: 通信与计算重叠，高效的梯度同步
- **使用**: 当模型大小适中、设备数量 < 100 时推荐

#### 完全分片数据并行（FSDP）
- **原理**: 模型参数、梯度、优化器状态全部分片，每个设备只保存部分
- **内存效率**: 可大幅降低单设备显存需求（理论上 ~1/N）
- **通信成本**: 比 DDP 多，但使能更大规模训练
- **应用**: LLaMA 65B+ 等大模型的标准方案

#### 序列并行（Sequence Parallelism）
- **目标**: 减少自注意力的计算和内存复杂度（O(L²) → O(L²/k)）
- **方法**: 沿序列维度分割，需要仔细的通信优化
- **应用**: 超长上下文模型（如100K tokens）的必要技术

#### 管道并行（Pipeline Parallelism）
- **原理**: 将模型分层分配到不同设备，流水线式前后向传播
- **挑战**: 设备利用率低、需处理气泡（bubble）
- **改进**: GPipe、1F1B 等调度算法
- **适用**: 极大规模模型（>100B参数）

### 5. 混合精度训练（Mixed Precision Training）

#### FP16（半精度浮点）
- **优点**: 内存使用减半、计算速度 2-3 倍
- **风险**: 数值精度低，梯度容易下溢（underflow）
- **解决**: 梯度缩放（loss scaling）防止梯度下溢

#### BF16（脑浮点）
- **特点**: 和FP32有相同的指数范围，但尾数较短
- **优势**: 对梯度下溢更鲁棒，无需损失缩放
- **流行**: 现代训练框架（PyTorch 2.0+、JAX）和硬件（TPU、A100）标准支持

#### Master Weights 策略
- **做法**: 用低精度（FP16/BF16）进行前后向计算，但用FP32保存模型权重
- **好处**: 结合低精度效率和FP32稳定性
- **开销**: 额外内存（通常可接受）

### 6. 检查点与恢复机制

#### 为什么需要检查点
- 训练通常持续数周，意外中断风险高
- 大规模分布式训练任何一个设备故障都可能导致全部重新训练
- 周期性保存检查点允许从最后一个有效点恢复

#### 检查点内容
- **模型权重**: 所有参数
- **优化器状态**: Adam 的动量、二阶矩等
- **随机数生成器状态**: 保证可重现性
- **训练步数与学习率**: 恢复时继续原有调度
- **分布式训练状态**: 各设备的同步信息

#### 内存优化技术
- **梯度累积**: 多个 batch 累积梯度后一次更新，扩展有效 batch size
- **梯度检查点（Gradient Checkpointing）**: 前向传播时不保存中间激活，反向时重计算，减少显存用量 30-50%
- **激活函数融合**: 如 Flash Attention 减少中间激活内存

### 7. 评估方法

#### 困惑度（Perplexity）
$$\text{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N} \log p(x_i)\right)$$

- **定义**: 模型在测试集上的交叉熵损失的指数
- **解释**: PPL 越低，模型对数据的拟合度越好
- **用法**: 快速评估预训练进度，监控过拟合

#### 下游任务评估
- **机器翻译**: BLEU 分数
- **文本生成**: ROUGE、METEOR 等
- **问答任务**: F1、准确率
- **分类任务**: 准确率、F1-score
- **原因**: 预训练损失与下游任务性能的相关性不完美，需多角度评估

#### 基准测试集
- **GLUE**: 通用语言理解基准（分类任务）
- **SuperGLUE**: 更难的任务集合
- **SQuAD**: 阅读理解
- **WikiText**: 按时间分割的语言建模测试集
- **C4**: Colossal Clean Crawled Corpus，与预训练分布更接近

## 实战应用

### 应用1：从头训练一个小型LLM
选择一个特定领域（如医学、法律）的文本，按以下步骤：
1. **数据收集**: 爬取专业网站、学术论文、专业书籍（100B-500B tokens）
2. **清洗与分词**: 使用 SentencePiece 创建专业领域词表
3. **训练设置**: 模型大小 1B-7B，按 Chinchilla 比例分配数据（约500B tokens）
4. **分布式训练**: 在 8-32 个 GPU 上使用 DDP 或 FSDP
5. **监控**: 每1000步保存检查点，每10000步评估困惑度
6. **输出**: 得到领域适配的基础模型，可用于后续微调

### 应用2：继续预训练（Continued Pre-training）
现成LLM适配新领域而无需完全重新训练：
1. **加载预训练模型**: 从 HuggingFace 加载（如 LLaMA-7B）
2. **领域数据**: 收集新领域数据（10B-100B tokens）
3. **低学习率**: 使用原始学习率的 10-20%，保留已学知识
4. **扩展词表**: 若新领域有特殊术语，可扩展 tokenizer
5. **高效微调**: 使用 LoRA（只训练适配器）节省资源

### 应用3：最优计算预算分配
若有 10^21 FLOPs 的计算预算：
1. **按 Chinchilla 分配**: 用 5×10^20 FLOPs 训练模型，5×10^20 FLOPs 处理数据
2. **计算模型大小**: N ≈ 5×10^20 / (6×10^8) ≈ 80B 参数
3. **计算数据量**: D ≈ 5×10^20 / (6×8) ≈ 10T tokens
4. **预估训练时间**: 在 1000 张 A100 上约 100-200 天
5. **资源规划**: 内存、通信带宽、存储均需充分估算

## 常见问题与陷阱

- **Q1: 数据去重真的有那么重要吗？**
  A: 是的。研究表明，去重能将模型困惑度降低 5-15%。近年流行的「网络数据质量危机」讨论正是因为互联网文本中重复率极高。

- **Q2: 为什么不能无限增加数据而不增加模型大小？**
  A: 违反 Chinchilla 定律会导致计算效率下降。过小的模型在海量数据上训练会严重欠拟合。

- **Q3: BF16 比 FP16 真的更好吗？**
  A: 在绝大多数情况下是。BF16 对梯度数值更鲁棒，训练更稳定，缺点是精度略低（但在LLM任务上影响不大）。

- **Q4: 预训练的 batch size 为什么要这么大（2M-4M tokens）？**
  A: 大 batch size 有效梯度估计更稳定，学习率可以更大，训练更快。但超过某个阈值后收益递减。

- **Q5: 检查点保存多频繁合适？**
  A: 通常每 1000-10000 步保存一次。太频繁增加存储 I/O，太稀疏则故障恢复成本高。应根据训练周期和故障概率调整。
