# RAG（检索增强生成）

## 定义

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将外部知识检索与语言模型生成相结合的技术，使 LLM 能够基于最新、特定领域的知识生成回答。

## 核心架构

```
用户问题 → 检索器 → 相关文档 → LLM + 文档 → 生成回答
```

### 1. 文档处理流程

1. **文档切分**: 将长文档切分为固定大小的块（chunks）
2. **嵌入（Embedding）**: 使用嵌入模型将文本块转换为向量
3. **存储**: 将向量存入向量数据库（Milvus、Chroma、FAISS 等）

### 2. 检索流程

1. **查询嵌入**: 将用户问题转换为向量
2. **相似度搜索**: 在向量数据库中查找最相似的文档块
3. **排序**: 按相似度分数排序，取 Top-K 结果

### 3. 生成流程

1. **上下文构建**: 将检索到的文档与问题拼接为提示词
2. **生成**: LLM 基于上下文生成回答
3. **引用**: 可选地标注引用来源

## 关键技术

### 向量数据库

| 数据库 | 特点 |
|--------|------|
| **FAISS** | Meta 开源，高效相似度搜索 |
| **Milvus** | 分布式，适合大规模数据 |
| **Chroma** | 轻量级，易于使用 |
| **Pinecone** | 云端托管，API 友好 |

### 检索策略

- **稠密检索**: 使用嵌入向量（适合语义匹配）
- **稀疏检索**: 使用 BM25 等传统方法（适合关键词匹配）
- **混合检索**: 结合稠密和稀疏检索

### 上下文优化

- **重排序（Re-ranking）**: 对检索结果进一步排序
- **上下文压缩**: 提取文档中与问题最相关的部分
- **多跳检索**: 多次检索-生成循环

## 与微调的对比

| 特性 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时更新向量库 | 需重新训练 |
| 数据需求 | 文档即可 | 需高质量训练数据 |
| 计算成本 | 低（仅推理） | 高（训练） |
| 幻觉问题 | 较少（有知识支撑） | 可能存在 |
| 可解释性 | 高（可追溯来源） | 低 |

## 应用场景

- **企业知识库问答**: 基于公司内部文档
- **客服机器人**: 基于产品手册和 FAQ
- **文档摘要与问答**: 基于论文、报告
- **代码助手**: 基于代码库和文档
