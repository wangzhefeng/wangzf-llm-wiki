# 提示词工程（Prompt Engineering）

## 定义

提示词工程是设计和优化输入提示，以引导大语言模型产生期望输出的技术和方法。

## 核心技术

### 1. 零样本提示（Zero-shot Prompting）

直接给出任务指令，不提供示例：

```
请将以下英文翻译成中文：
"The quick brown fox jumps over the lazy dog."
```

### 2. 少样本提示（Few-shot Prompting）

提供 1-5 个示例，帮助模型理解任务格式：

```
英文 → 中文
"Hello" → "你好"
"Good morning" → "早上好"
"The weather is nice" → ?
```

### 3. 思维链（Chain-of-Thought, CoT）

引导模型分步推理：

```
问题：小明有 5 个苹果，给了小红 2 个，又买了 3 个，现在有几个？
回答：让我们一步一步思考。
1. 小明一开始有 5 个苹果
2. 给了小红 2 个，剩 5-2=3 个
3. 又买了 3 个，有 3+3=6 个
所以答案是 6 个。
```

### 4. ReAct（Reasoning + Acting）

结合推理和行动，适用于 Agent 场景：

```
Thought: 我需要搜索"2024年诺贝尔物理学奖得主"
Action: Search["2024年诺贝尔物理学奖得主"]
Observation: John Hopfield 和 Geoffrey Hinton
Thought: 答案是 John Hopfield 和 Geoffrey Hinton
```

### 5. 自洽性（Self-Consistency）

多次采样生成多个推理路径，选择最一致的答案。

### 6. 思维树（Tree of Thoughts, ToT）

将推理过程构建树结构，在每个节点评估多个分支。

### 7. APE（Automatic Prompt Engineering）

使用 LLM 自动生成和优化提示词。

## 提示词结构

一个好的提示词通常包含：

1. **角色定义**: "你是一个专业的翻译助手"
2. **任务描述**: "请将以下英文翻译成中文"
3. **约束条件**: "保持原文语气，使用简洁表达"
4. **输出格式**: "请以 JSON 格式返回"
5. **示例**（可选）: 提供 1-2 个输入输出示例

## 最佳实践

- **明确具体**: 避免模糊描述
- **分步引导**: 复杂任务分解为多步
- **提供示例**: 少样本提示显著提升质量
- **约束输出**: 指定格式、长度、风格
- **迭代优化**: 根据输出调整提示词
