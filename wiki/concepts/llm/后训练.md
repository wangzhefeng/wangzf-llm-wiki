# 后训练（Post-training）

## 定义与核心要点

后训练是在预训练语言模型基础上，通过指令微调（SFT）和强化学习对齐（RLHF）等方法，使模型学会遵循人类指令、按照人类偏好生成内容的过程。预训练的模型虽然具有强大的语言理解能力，但往往不能很好地按照用户指令执行任务、可能包含有害内容或事实错误。后训练通过人类反馈驱动的优化，构建了从"能生成文本"到"能帮助用户"的关键桥梁。

## 为什么重要

虽然预训练提供了强大的基础，但预训练模型存在三个核心问题：
1. **指令跟随能力差**：模型可能不理解或忽视用户指令
2. **输出可能有害**：包含虚假信息、有偏见或不安全内容
3. **难以控制**：模型生成的内容方向不可控

后训练通过引入人类反馈，将模型的行为与人类价值观对齐，这是让 LLM 成为实用工具的必要条件。从 ChatGPT 的成功可以看出，后训练的质量往往比预训练数据量更能决定用户体验。

## 核心原理

### 1. 指令微调（Supervised Fine-Tuning, SFT）

#### 基本思路
在有标注的指令-答案对上进行标准的监督学习，使模型学习从指令到期望输出的映射。

#### 数据构成
- **指令-答案对数据**：从 10K 到 100K 对不等
- **来源**：人工标注（如 OpenAI 的 instructGPT 标注者）、众包（Amazon Mechanical Turk）、自合成（用强模型生成弱模型的训练数据）
- **质量标准**：答案准确、详细、安全、无偏见

#### 训练方法
```
标准交叉熵损失：L = -log P(answer | instruction)
直接在预训练模型上继续训练，通常：
- 学习率：原始预训练学习率的 1-10%
- Batch size：较小（32-256），因为数据量少
- 训练周期：通常 1-3 个 epoch
```

#### 实践要点
- **防止灾难遗忘**：使用较低学习率和较少迭代，保留预训练知识
- **数据多样性**：涵盖多种任务类型（问答、摘要、翻译、代码生成等）
- **样本权重**：重要任务可赋予更高权重

### 2. 强化学习对齐（Reinforcement Learning from Human Feedback, RLHF）

RLHF 是一种系统的方法，使模型的生成行为更符合人类偏好，而不是单纯的准确性。

#### 核心三步

**第一步：收集对比标注数据**
- 给定一个 prompt，用 SFT 模型生成两个候选答案
- 人类标注者选择更好的答案（更有用、更安全、更符合指令）
- 收集数千个这样的对比标注对（如 OpenAI 的 InstructGPT 用 33K 对）

**第二步：训练奖励模型（Reward Model, RM）**
- 使用对比标注数据训练一个分类器，预测"答案 A 比答案 B 更好"的概率
- 损失函数：
  ```
  L_RM = -log(σ(r(x, y_w) - r(x, y_l)))
  其中 r(x, y) 是奖励模型对 (prompt, answer) 的打分
  y_w 是人类偏好的答案，y_l 是非偏好的答案
  ```
- 奖励模型充当"人类评判官"的代理

**第三步：用奖励模型优化策略**
- 使用 PPO（Proximal Policy Optimization）或其他强化学习算法
- 目标函数包含两部分：
  ```
  L = E[r(x, y) - β·KL(π(y|x) || π_ref(y|x))]
  其中 β 是 KL 散度权重，π_ref 是 SFT 模型（防止偏离过远）
  r(x, y) 是奖励模型的打分
  ```

#### RLHF 的挑战
- **奖励模型过度拟合**：少量标注数据可能导致奖励模型学到虚假信号
- **奖励黑客（Reward Hacking）**：模型学会"欺骗"奖励模型而非真正改进
- **计算成本高**：需要不断推理生成新样本，计算量是 SFT 的 10-100 倍

### 3. 直接偏好优化（Direct Preference Optimization, DPO）

DPO 是 2023 年提出的替代方案，避免了 RLHF 的复杂性。

#### 核心思想
不显式训练奖励模型，而是直接从偏好数据中学习。

#### 数学原理
从对比标注（A 优于 B）推导出隐式奖励函数，然后直接优化：
```
L_DPO = -log σ(β log(π(y_w|x) / π_ref(y_w|x)) - β log(π(y_l|x) / π_ref(y_l|x)))
```

#### 优势
- **更简单**：只需一个模型和标注数据，无需额外的奖励模型
- **更高效**：训练时间与 SFT 相近，无需强化学习的复杂算法
- **性能可比**：实验表明 DPO 与 RLHF 性能相当甚至更好

### 4. 其他对齐方法

#### GRPO（Generative Reward Policy Optimization）
- 改进的强化学习方法，使用更稳定的梯度估计
- 相比 PPO 收敛更快、更稳定

#### KTO（Kahneman-Tversky Optimization）
- 基于行为经济学的对齐方法
- 分别优化"好的"和"坏的"样本

#### 宪法 AI（Constitutional AI）
- 使用一组原则（宪法）引导模型的行为
- 不依赖人工标注者的具体偏好，而是依赖原则

### 5. 安全与对齐评估

#### 多维评估
- **有用性（Helpfulness）**：是否有效解决用户问题
- **诚实性（Honesty）**：是否给出真实信息，是否表达不确定性
- **无害性（Harmlessness）**：是否避免生成有害、有偏见、不当内容

#### 评估方法
- **自动评估**：用强模型（如 GPT-4）评判弱模型输出
- **人工评估**：众包或专业标注者评分
- **安全基准**：如 TruthfulQA、BBQ（偏见评估）等

## 实战应用

### 应用1：从开源模型构建定制 AI 助手
1. **选择基础模型**：如 Llama-2-7B（已预训练）
2. **收集指令数据**：为目标领域或任务设计 5K-10K 指令-答案对
3. **SFT 微调**：用低学习率（1e-4）训练 1-2 个 epoch
4. **可选：RLHF**：收集 1K-2K 对比标注，训练奖励模型并进行 PPO
5. **部署**：得到针对目标任务优化的模型

### 应用2：安全对齐（拒绝有害请求）
1. **收集拒绝数据**：有害指令 + 模型应如何礼貌拒绝的答案（5K 对）
2. **混合训练**：有益任务数据 + 拒绝数据，比例 9:1
3. **安全评估**：用已知有害请求集合（jailbreak 尝试）测试模型
4. **迭代改进**：根据失败案例补充训练数据

### 应用3：多语言对齐
1. **跨语言数据**：收集多语言指令-答案对
2. **平衡训练**：按语言比例分配数据
3. **零样本转移**：模型在未见过的语言上也能遵循指令
4. **文化适配**：考虑不同文化背景下对"有用"的定义可能不同

## 常见问题与陷阱

- **Q1: SFT 会导致模型遗忘预训练知识吗？**
  A: 可能会（灾难遗忘）。用低学习率、少迭代、混合数据（包含通用任务）等方法缓解。

- **Q2: 为什么 RLHF 比 DPO 计算更贵？**
  A: RLHF 需要两个模型（SFT + 奖励模型）且需反复采样新生成进行强化学习。DPO 直接用已有的标注对，更高效。

- **Q3: 人类标注的偏好数据一定准确吗？**
  A: 不一定。标注者可能有偏差或意见不一。高质量的标注需要清晰的标注指南和多个标注者的共识。

- **Q4: 后训练用的数据量真的很少吗？**
  A: 相对预训练确实少很多（1K vs 1T tokens），但对效果影响很大。质量往往比数量更重要。

- **Q5: 模型能学会"明确拒绝"有害请求吗？**
  A: 能，但需要显式训练。仅用好数据微调可能学不到拒绝。需要把拒绝例子作为"好"的样本。
