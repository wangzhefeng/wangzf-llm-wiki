# 分词

## 一句话定义

分词（tokenization/segmentation）是将连贯的文本序列切分成有意义的词汇单位的过程，是自然语言处理的第一步。

## 在知识体系中的位置

分词是 NLP 的基础任务之一，位于文本处理流水线的最上游。几乎所有后续的 NLP 任务（词性标注、NER、句法分析、文本分类）都依赖分词的结果。英文有天然的空格分隔符，但中文需要特殊的分词算法。

### 知识关联
- **前置步骤**：文本清洗（去除噪声、标准化）
- **后续步骤**：[[词性标注]]、[[特征提取]]、模型输入
- **同级任务**：[[命名实体识别]]、[[句法分析]]

## 核心原理与方法

### 三代分词方法

**1. 规则分词（1980s-1990s）**
- 最大匹配法：从左到右贪心匹配词典中的最长词
- 原理简单，但难以处理歧义（如"北京大学"vs"北京 大学"）
- 当代仍用于部分领域（医学、法律专有词典）

**2. 统计分词（1990s-2010s）**
- 隐马尔可夫模型（HMM）：将分词建模为序列标注任务
- 条件随机场（CRF）：解决标签依赖问题
- 基于字或词的 N-gram 语言模型
- 精度显著提升，成为工业标准

**3. 神经分词（2010s-至今）**
- 双向 LSTM（BiLSTM）：捕捉上下文依赖
- Transformer & BERT：动态字级表示
- 端到端学习，精度达到 95%+ 在通用语料库

### 核心概念：序列标注

分词通常被建模为**字级序列标注**问题，对每个字符标记 `B`（词首）或 `I`（词内）：

```
文本：北京大学
标签：B  I  B  I
分词结果：北京 / 大学
```

## 实战应用（3 个案例）

### 案例 1：中文分词工具链对比

**jieba 分词**（Python）：
```python
import jieba
text = "我爱自然语言处理"
words = jieba.cut(text)  # 输出：我/爱/自然/语言/处理
```
- 优点：易用、支持自定义词典
- 缺点：精度有限（90-92%）、更新慢

**spaCy 分词**（多语言）：
```python
import spacy
nlp = spacy.load("en_core_web_sm")
doc = nlp("I love NLP")
tokens = [token.text for token in doc]  # 输出：['I', 'love', 'NLP']
```
- 优点：多语言、工业级、快速
- 缺点：英文优于中文

### 案例 2：歧义处理

输入："我说不能输"
- 错误分词：我/说/不/能/输
- 正确分词：我/说/不能/输（"不能"是一个词）

现代分词算法通过训练数据和语言模型自动学习，无需手工规则。

### 案例 3：领域适配

医学文本中的特殊术语（"β受体"、"ACE抑制剂"）容易被误分。解决方案：
1. 构建领域词典
2. 使用领域特定模型
3. 后处理规则修正

## 常见问题

**Q: 中文和英文分词的根本区别是什么？**
A: 英文有天然的空格分隔符（约 100K 词汇），分词相对简单。中文无分隔符，词汇量更大（100K-200K），歧义更多，分词更复杂。

**Q: OOV（未见词）问题如何处理？**
A: 子词分割（Byte Pair Encoding、WordPiece）将未见词拆分为已知子词，BERT 等预训练模型内置此机制。

**Q: 分词精度多少算好？**
A: 通用文本 95%+ 即可使用，专业领域可能需要 98%+。精度与计算成本需权衡。

**Q: 为什么有些系统跳过分词，直接用字级处理？**
A: 预训练模型（BERT）学会了隐式分词，无需显式分词步骤，但显式分词仍在许多场景保留，如搜索引擎倒排索引构建。

**Q: 分词对下游任务有多大影响？**
A: 中文 NLP 中分词错误直接影响精度（下游任务精度 = 分词精度 × 后续任务精度）；英文和预训练模型中影响较小。
