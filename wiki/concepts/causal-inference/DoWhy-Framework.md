# DoWhy Framework（DoWhy 框架）

## 定义

DoWhy 是由微软开源的端到端因果推断 Python 库。它统一了 **Pearl 的因果图模型**与 **Rubin 的潜在结果框架**，提供了一套**原则性的四步骤工作流**，使用户能够以明确的假设进行因果推断，并自动验证估计的鲁棒性。

## 设计哲学

### 三大原则

1. **显式化假设（Explicitness）**
   - 所有因果假设必须明确地编码为因果图或变量集合
   - 避免隐含假设，便于审视与讨论

2. **分离识别与估计（Separation）**
   - 识别阶段（Identification）：基于因果假设，确定是否可识别
   - 估计阶段（Estimation）：选择合适的统计方法进行估计
   - 两个阶段独立，灵活组合

3. **自动鲁棒性检查（Refutation）**
   - 内置多种反驳方法自动验证估计
   - 减少假设被违反时的盲区

## 四步骤工作流

### 1️⃣ 建模（Model）

**目标**：将因果问题形式化为因果图

**输入形式**：

**A. 因果图方式**
- GML（Graph Modeling Language）格式
- DOT（Graphviz）格式
- 字符串描述

**示例**：
```
digraph {
  Z -> X;
  Z -> Y;
  X -> Y;
}
```

**B. 命名变量集合方式**
```python
common_causes = ['Z']  # 混杂因子
instruments = ['IV']   # 工具变量
effect_modifiers = ['M']  # 效应修改变量
```

**特点**：
- 图不需要完整，DoWhy 自动将未指定的变量视为潜在混杂因子
- 支持多种图格式，易于版本控制

### 2️⃣ 识别（Identify）

**目标**：基于因果图，确定因果效应是否可识别，并找到识别公式

**输入**：阶段 1 的因果图

**工作机制**：
- 应用 Pearl 的基于图的准则
- 枚举所有可能的识别路径
- 支持的准则：

| 准则 | 适用情景 | 描述 |
|---|---|---|
| **后门准则** | 存在后门路径 | 找一个变量集合阻断所有后门路径 |
| **前门准则** | 存在中介变量 | 即使有不可观测混杂因子，仍可识别 |
| **工具变量** | 存在排除限制 | 找工具变量识别处理效应 |
| **中介分析** | 分解直接与间接效应 | 识别直接和间接效应 |

**输出**：
- 识别公式（非参数化表达）
- 所需假设清单
- 可选的多种识别策略

### 3️⃣ 估计（Estimate）

**目标**：使用统计方法估计识别公式中的参数或期望值

**支持的估计方法族群**：

**基于倾向分配的方法**
- 倾向评分分层（Propensity Stratification）
- 倾向评分匹配（PSM）
- 逆向倾向加权（IPW）

**基于结果模型的方法**
- 线性回归（OLS）
- 广义线性模型（GLM）

**基于工具变量的方法**
- 工具变量估计（二元工具）
- 两阶段最小二乘法（2SLS）
- 非连续回归（RDD）

**基于前门准则的方法**
- 两层线性回归

**外部集成**
- 调用 EconML（异质性处理效应）
- 调用 CausalML（机器学习方法）

**特点**：
- 统一接口，用户无需关心底层实现
- 自动处理样本权重、缺失值等
- 支持置信区间与统计显著性检验

### 4️⃣ 反驳（Refute）

**目标**：通过多种鲁棒性检查验证因果估计的正确性

**内置反驳方法**：

| 反驳方法 | 原理 | 预期结果 |
|---|---|---|
| **添加随机混杂因子** | 添加与处理/结果无关的随机变量 | 因果效应不改变 |
| **安慰剂干预** | 将真实处理替换为随机变量 | 因果效应归零 |
| **虚拟结果** | 将结果替换为随机变量 | 因果效应归零 |
| **模拟结果** | 基于数据生成过程模拟数据 | 估计效应 ≈ 真实参数 |
| **未观测混杂敏感性** | 假设存在额外混杂因子 | 效应对混杂的敏感性 |
| **数据子集验证** | 在样本子集上重复估计 | 结果稳定 |
| **自助法验证** | 在自助样本上重复估计 | 结果稳定 |

**特点**：
- 自动化，无需手动实现
- 多角度验证，提高信心
- 返回 p 值与置信区间

## 核心优势

### 1. 两框架统一
- **何处统一**：识别阶段用因果图（Pearl），估计阶段用潜在结果框架（Rubin）
- **何故统一**：因果图提供识别，潜在结果提供估计，互补
- **何用统一**：一个工具，完整因果推断

### 2. 简化因果推断流程
- **识别 ≠ 估计**：避免混淆"能否推断"与"如何估计"
- **显式假设**：所有假设一目了然，易审视与讨论

### 3. 自动化假设验证
- **反驳方法内置**：无需手写代码
- **多角度检验**：单一反驳不足，多方法增强信心

### 4. 灵活扩展
- 支持自定义估计器（实现接口）
- 支持自定义反驳方法
- 积极维护，功能持续扩展

## 实际应用流程

### 典型案例：评估政策效应

**背景**：新政策是否有效？

**步骤**：
1. **建模**：制定因果图
   ```
   政策变量 → 结果
   混杂因子 ↗  ↓
   ```

2. **识别**：应用后门准则
   - 需控制混杂因子
   - 识别公式：ATE = E[Y|do(Policy=1)] - E[Y|do(Policy=0)]

3. **估计**：选择倾向评分或回归
   - 获得点估计与置信区间
   - 如 ATE = 0.15 [0.10, 0.20]

4. **反驳**：检验假设
   - 添加随机变量：ATE 改变吗？（不改变 ✓）
   - 敏感性分析：未观测混杂因子有多强才能改变结论？

### 代码示例思路

```python
import dowhy
from dowhy import CausalModel

# 1. 建模
model = CausalModel(
    data=data,
    treatment='policy',
    outcome='result',
    common_causes=['confound']
)

# 2. 识别
identified_estimand = model.identify_effect()

# 3. 估计
estimate = model.estimate_effect(
    identified_estimand,
    method_name='backdoor.propensity_stratification'
)

# 4. 反驳
refute = model.refute_estimate(identified_estimand)
```

## 限制与注意事项

### 1. 因果图的正确性
- DoWhy 的识别步骤依赖因果图的正确性
- 错误的图 → 错误的识别 → 错误的估计
- **无法从数据验证因果方向**，需要领域知识

### 2. 可忽略性假设
- 任何观察性研究方法都无法验证可忽略性
- 需要理由相信"所有混杂因子都被观测"
- DoWhy 的反驳方法可检验敏感性，但不能证明假设成立

### 3. 样本大小与变量维度
- 当协变量维数高时，倾向评分估计可能困难
- 推荐使用机器学习方法（与 EconML 集成）
- 但高维下识别困难增加

### 4. 软件实现与理论
- DoWhy 的某些功能可能与学术论文实现略有差异
- 需要对底层方法的理解才能正确使用

## 与其他工具的对比

| 工具 | 焦点 | 优势 | 劣势 |
|---|---|---|---|
| **DoWhy** | 完整工作流 | 识别+估计+反驳一体化 | 可能过度简化 |
| **CausalML** | 机器学习方法 | HTE、元学习者 | 缺乏识别讨论 |
| **EconML** | 异质性效应 | 置信区间、解释性 | 主要用于估计 |
| **R 包 causaleffect** | 识别 | 图论识别自动化 | 仅识别，不估计 |
